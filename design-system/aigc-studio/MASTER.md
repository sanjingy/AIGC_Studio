## 0. 产品定位（决定一切设计判断）

```
产品类型   内部生产工具 / 工作台（不是营销站，不是内容消费站）
主角       用户生成的图片和视频
用户       创作者，长时间连续使用，一次盯 60 个镜头
使用场景   桌面为主，高密度，键盘友好
```

**第一原则：界面必须退到画面后面。**
UI 的任何颜色都不能干扰用户对生成画面的判断——这直接排除了带色底、
高饱和边框、大面积品牌色。调色台的墙是中性灰，就是这个道理。

## 1. 初版检索记录（2026-08-16，留作来历）

首版走 `ui-ux-pro-max` 检索，命中 Minimalism & Swiss Style + Plus Jakarta
Sans + slate 中性色 + teal 主色。**这套外观已被 2026-09-21 覆盖**：
teal 是检索给的通用 SaaS 主色，放在影像生产工具上没有任何来历，
换谁做同类产品都会得到它。保留这段是为了说明当初为什么那样选，
不是让人照着它改回去。

字体那条结论仍然成立并被本轮沿用：**中文不上 Web 字体**。中文字库几 MB，
对每天开一整天的工作台是净负担。本轮进一步把拉丁部分的 Plus Jakarta Sans
也去掉了——它没有被 `@font-face` 或 link 加载过，实际只在装了该字体的机器上
生效，等于一条不可复现的外观差异。

## 2. 颜色 — Studio Ledger

六个命名值定调，其余全部由它们派生。值写在
`apps/web/app/globals.css` 顶部，组件一律通过语义 token 取色。

| 名称 | 值 | 角色 |
|---|---|---|
| `studio-black` | `#101114` | 外层背景、影院式留白 |
| `graphite` | `#191B20` | 导航与工作面 |
| `slate-card` | `#23262D` | 抬起的编辑面板 |
| `slate-raised` | `#2B2F37` | 面板内再抬一层：输入框、内嵌行 |
| `paper` | `#F1F0EB` | 主文字，以及全站唯一的浅色面（剧本纸） |
| `ultramarine` | `#8296FF` | 主要交互、选中、焦点 |
| `safety-amber` | `#F2BE5C` | 生成中、待确认、拍摄提示 |

### 两个强调色的分工不可互换

- **ultramarine = 你可以动它。** 按钮、选中态、焦点环、当前阶段。
- **safety-amber = 系统正在做，或在等你。** 生成中、待确认门、过期提示。

两者语义不重叠，所以任何位置都不会出现"这里用哪个都行"的情况。
这也是本轮没有落进「暗底 + 单一荧光色」那个通用暗色方案的原因之一：
单强调色的界面必然要靠亮度区分"可点"和"在跑"，而那两件事应该一眼分得开。

成功与危险保留独立语义色，不复用上面两个：
`success #6FCF97` / `danger #F2776F`。

### 派生与实测

| token | 值 | 最差底色上的对比度 |
|---|---|---|
| `fg` | `#F1F0EB` | 11.76:1（on slate-raised） |
| `fg-muted` | `#B6B9C0` | 6.83:1（on slate-raised） |
| `fg-subtle` | `#9AA0AA` | 5.10:1（on slate-raised） |
| `primary` | `#8296FF` | 4.96:1（on slate-raised） |
| `running` | `#F2BE5C` | 7.86:1 |
| `success` | `#6FCF97` | 7.06:1 |
| `danger` | `#F2776F` | 4.89:1 |

`fg-subtle` 原定 `#8E939C`，在 `slate-raised` 上只有 **4.35:1**，不达 AA，
实测后提到 `#9AA0AA`。这类调整必须实测，不能凭色阶名义挑。

按钮前景色单独给了 `--danger-fg`：`#F2776F` 是浅色，压白字只有 2.6:1，
暗色主题下危险按钮必须压墨色（`#101114`，6.87:1）。

### 剧本纸面

`.ff-paper` 是**全站唯一的浅色面**，只给剧本/故事正文用。
它在自己作用域内重定义整套语义 token，所以子组件照常写 `text-fg-muted`，
不必知道自己在纸上。纸上的 ultramarine 压到 `#3B4BC4`（6.16:1），
纸上的 `fg-subtle` 取 `#5C5F68`（在两种纸色上 5.06 / 5.59）。

为什么只有这一处：剧本本来就是纸。这个对比是有来历的，不是为了"换个花样"。
复用到别处它就退化成装饰。

## 3. 字体

```
sans   -apple-system / Segoe UI / PingFang SC / Microsoft YaHei / Noto Sans SC
mono   ui-monospace / SF Mono / Cascadia Mono / Segoe UI Mono / Consolas
```

**不引入任何需要联网下载的字体。** 两条栈都写在 `--font-sans` /
`--font-mono` 上，`app/layout.tsx` 不再内联 `fontFamily`——两处各写一份必然分叉。

### 等宽只给标识用

`.code` 类 = `font-mono` + `tabular-nums`。**只用于**镜号、时间码、
Credits、版本号、模型 id、文件大小、日期。

不要把所有小标签都改成等宽大写——那是通用「数据仪表盘」的写法，
在这里只会让界面更像后台，不像片场。

### 标题的性格来自字重、字距和行长，不来自换色

- 标题统一 `letter-spacing: -0.02em`，字重 600–650。
- 正文行长 ≤ 68ch；剧本正文 `leading-6`。
- **禁止**：标题里只给一个词换色/加粗/斜体；标题上方加一行全大写 eyebrow。
  两者都是生成式设计最常见的痕迹，本轮已从代码里清除干净。

### 字号阶（工作台密度）

```
xs 12/16   sm 13/18   base 14/20   lg 16/24   xl 20/28   2xl 24/32
```

正文 13px 偏离 16px 基准是有意的，用对比度 ≥7:1 补偿。

## 4. 几何：半径编码「这是画框还是控件」

```
--radius-frame  2px   承载画面的东西：画框、面板、账式行、标签、对话框
--radius-md     8px   控件：按钮、输入框、导航项
--radius-sm     4px   焦点环
full 9999px           只给圆点、头像、spinner
```

画面是矩形，所以承载画面的容器几乎不圆角；圆角留给能按下去的东西。
这条规则是可学的：用户扫一眼就知道哪些能点。

**这直接取代了旧版「默认 4–6px，头像和状态药丸用 full」。**
状态标签本轮全部从胶囊改成方角——它是场记单上的一栏，不是通用 badge。

间距阶不变：`4 / 8 / 12 / 16 / 24 / 32 / 48`。

## 5. 布局

> 旧版 §5 描述的四栏工作台（`app/(app)/...`、`project-composer`）
> **已于 2026-09-03 随 ADR-030 删除**，那段版式图不再对应任何代码。
> 现在唯一的壳是 `/freeflow`。

### 唯一的大胆元素：胶片连续带

全站只有一个地方允许张扬，就是阶段条和镜头序列的**胶片连续带**：

```
┌ ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ●┐   ← 齿孔
│ 01 故事  │ 02 剧本  │ 03 角色  ║ 04 镜头 ║ 05 生成    │
│ 已就绪   │ 已就绪   │ 已就绪   ║ 当前阶段 ║ 待开始     │
└ ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ● ●┘
                                 ↑ 当前阶段「在片门里」
```

- **帧与帧之间没有间距，只有一条接片线。** 制作流程本身是连续的，
  跳不过任何一格；做成一排带间隙的圆角卡片就把这件事说错了。
- 齿孔是**全站唯一的纹理**，只出现在这条带子上。别处不许再铺网格、
  颗粒或刻度线——纹理一旦铺满就不再是标志。
- 带子必须表达**真实**阶段、镜号、状态或时长。它不是装饰条。
- **只读。** 阶段图在后端 `orchestrator._NEXT` 里，前端重排不了，
  做成可拖拽就是假入口。
- 带子自己横向滚，不撑宽页面，因此所有断点都在，不靠隐藏来适配。

### 场记板字段组

项目身份用「字段名 / 值」表达，不用面包屑：

```
项目            路线              镜头   更新
第七夜          NOVEL_TO_ANIME     42    09/21 07:26
```

**没有值的字段整条不渲染，不留空槽**——场记板上没写的就是还没定。
数值字段走 `.code`，列对得齐。

### 页面结构

| 页面 | 结构 |
|---|---|
| 全局首页 | 先创作输入（项目名 + 原文，「只创建项目」与「开始生产」两个动作分开），再「继续制作」（最近编辑的项目，最大一块画面）+「需要你处理」（账式行），最后近期项目（按最近编辑，最多 8 个）。**没有营销 hero**，见「首页与资产（P3A）」 |
| 项目片单 | 宽窄交错的 contact sheet：每 5 格一循环（3 窄 + 2 宽），两行铺满 6 列 |
| 项目工作台 | 场记板 + 连续带横贯顶部，左导航，主创作面，右侧 300px 上下文栏（`xl` 以下变抽屉，内部是 `.ff-rail`） |
| 项目概览 | **制作板 `.ff-board`**：通告条 → 写库动作 → 待办与制作进度 → 产出台账。四块体量刻意不等，见下 |
| 分镜页 | **接触表在前**，选中那一镜的工作区在后。不把整页做成长表单 |
| 资产库 | 范围（全部项目 / 某个项目）+ 搜索 + 真实类型筛选，下面是**光桌 `.ff-lighttable`**（真实画面，按原始画幅对齐排布）+ **档案列 `.ff-dockets`**（角色/场景/Skill/无预览文件，索引卡），两层体量分得开。项目内资产页是同一个组件，范围固定为本项目 |
| 模型 / 任务 / 项目设置 | 账式行与分组（`.ff-ledger`），不用重复大卡片。任务分「生成记录」与「执行队列」两种语义，项目内与全局 `/freeflow/tasks` 共用一个账本（`TaskLedger`），见「任务与设置（P3B）」 |
| 登录页 | 左：产品身份 + 五格连续带列出真实产出链路；右：表单。窄屏只留表单 |

> `/freeflow/billing` 与 `/freeflow/settings` 目前只是 `GlobalPlaceholder`
> 占位路由：直接输 URL 能开（200），但全局导航里没有入口，页面只有一句
> 「此功能尚未接入」。**它们没有套 `.ff-ledger`**——没有账可排的页面套上账本
> 外壳，就是把占位伪装成功能。等后端有内容时再按本节接。

### 元信息用结构表达，不用中间点串接

`A · B · C` 这种串是生成式设计最常见的痕迹之一。本轮全部改掉：
计数类改成中文句子（`3 个节点，2 场景`），"描述 + 日期"改成
`flex justify-between` 的两栏——左边描述，右边等宽日期。
**这是结构，不是分隔符**，扫一列的时候日期天然对齐。

### 制作板：项目概览的四块（`.ff-board`）

概览回答四个问题，**顺序就是读的顺序，体量刻意不等**：

```
┌ 通告条 .ff-board-call ────────────────────────────────────┐
│ 现在拍到              下一动作                              │
│ 分镜确认            [ 去确认分镜 ]  为什么要做这一步        │
└───────────────────────────────────────────────────────────┘
  写库动作（AdvanceAction / GateActions）—— 全页唯一会花钱的按钮
┌ .ff-board-split ────────────┬────────────────────────────┐
│ 需要你处理（账式行，左侧竖边 │ 制作进度（.ff-meter 方头尺）│
│ 按 review/attention/danger）│ 角色基准图 / 场景参考图 / 分镜图 │
└─────────────────────────────┴────────────────────────────┘
┌ 产出台账 .ff-ledger ──────────────────────────────────────┐
│ 01 路线  02 剧本  03 角色  04 场景  05 分镜  06 出图        │
└───────────────────────────────────────────────────────────┘
```

- **通告条是全页最大的字**，右边是全页唯一的主按钮。打开概览先看它。
- 待办**只在真有事时出现**，不占位。
- 进度尺 `total === 0` 时**不画空槽**，写「这个项目还没有这一类」——
  空槽等于承诺一个还不存在的产出。
- 台账的 `01`–`06` 是**真实生产序列**（§7 检查清单允许编号的唯一条件）；
  02–04 三段在序号槽左侧共用一条竖线表示并行，不是三行箭头。

### 账式行（`.ff-ledger` / `.ff-meter`）

数据页用行和分组，不用重复大卡片。三层：

```
.ff-ledger          账本外壳（1px 边框，2px 圆角，无阴影）
  -head             栏头：标题 + 筛选。筛选属于账本，不浮在外面
  -note             一段说明，跟在栏头后
  -row              条目；-key 定宽标签 / -val 内容 / -num 右对齐等宽数字
  -empty            空账
```

- `-row[data-form]` 给带控件的行多一档行高（控件 32px，挤在只读行里会贴边）；
  599px 以下改竖排。
- `-row[data-flag]` 左侧一条 2px 竖边：`review` 主色 / `attention` 琥珀 /
  `danger` 红。和阶段条「片门」是同一套语言。
- **筛选器放在 `-head` 里**，因为筛选就是「看这本账的哪一栏」，
  不是账本外面另起的一排胶囊；每个筛选带真实条数。
- `.ff-meter` 是方头进度槽，`data-tone` 取 `running` / `done`。
  制作进度是「拍了多少格」，是计数不是百分比，所以不做圆角胶囊。

在用：`project-overview` / `task-ledger`（经 `task-center` 与全局任务页） / `generation-records` / `project-settings` /
`model-catalog-page`。`components/ui/panel.tsx` 的 `PanelHeader` 与 `Metric`
因此成了死代码，已删；`Panel` 仅剩 `Disclosure` 在用。

### 光桌与档案列（`.ff-lighttable` / `.ff-plate` / `.ff-docket`）

资产库分两层，**体量必须分得开**：

```
光桌 .ff-lighttable —— 只放 type === "image"
┌──────────┬────────────────┬─────┐   同一行高度相同，
│  4:3     │     16:9       │ 3:4 │   宽度随真实画幅变化
└──────────┴────────────────┴─────┘
档案列 .ff-dockets —— 角色/场景/Skill/无预览文件
│▌角色 沈砚   3 个版本          09/21 │  ← 窄、扁、密，左侧书脊标类别
│▌场景 天台   2 张参考          09/20 │
```

- 排布靠 `flex-grow: var(--ar)` + `flex-basis: calc(var(--ar) * 132px)`，
  `--ar` 来自 `assets` 表真实的 `width/height`（null 退回 16:9）。
  `::after` 是不可见弹性尾块，最后一行不会被拉成怪比例。
- 文件名与尺寸**烧在画框下沿的渐隐里**（`.ff-plate-burn`），不另起白底条。
- `.ff-plate[data-empty]` 用网格底纹 + 小图标，明确是「这里没有画面」，
  不是「还在加载」。
- **视频与音频故意走档案列**：这条链路没有转码，拿不到封面帧，
  给它空画框等于承诺一个不存在的缩略图。
- 书脊色：character 主色 / scene `--rf-agent` / skill 琥珀。

### 右栏轨（`.ff-rail`）

右侧上下文栏**不是三块等大面板**。三块内容重要性本来就不同：

```
当前阶段    ← 唯一有背景的一块，它是这条轨上的主语（.ff-rail-now）
──────────
运行任务 2  ← 平的清单，一行一条（.ff-rail-list / -item）
──────────
一致性档案 5
```

块与块之间只有一条分隔线，没有卡片外壳；标题行右端是真实条数（等宽）。
空态直接写一句话，不套虚线框。
给三块同样的边框和内边距，等于在说「一样重要」——那是 SaaS 卡片堆的默认，
不是这个产品的信息结构。

### CSS 分层：值写在组件里，不写巨型后代选择器

左栏导航原先有一层
`.ff-studio .ff-workbench-sidebar nav > section|div|h2|ul|li>a` 的 override，
和 `sidebar-nav-group.tsx` 的工具类互相覆盖。**已全部拆回组件**
（内边距、行高、字号、字重、`max-md:` 变体都写在 className 上），
`studio.css` 里现在 `.ff-workbench-sidebar nav` 出现 **0 次**。

规则：`studio.css` 只定义**自己命名的结构类**（`.ff-*`），
不去改别人用工具类写好的元素。两套规则一旦对同一个属性发言，
以后每次改都要先猜哪边赢。

### 故事/剧本工作台（P2A，`/freeflow/projects/[id]/story`）

与分镜页同一套暖黑金色与紧凑顶栏、模块栏。本页**不画**胶片连续带和右栏：
门、返工、改动记录都在主区，右栏再占 300px 只会挤掉正文。

- **左目录 230–280px**：搜索 → 故事·情节目录 → 完整剧本 → 集（可展开）→ 场。
  集与场按真实 `screenplay.episodes[].scenes[]` 列出，重复集号、重复场号照原样
  列两行，不合并、不猜。搜索只筛目录，不导航；正在编辑的场即使被筛掉也钉在
  目录里并标「有未保存的改动」。窄于 `lg`（1024）收成「目录」按钮 + 左侧抽屉，选中即关。
- **主区四视图**：故事（情节目录 + 门①）、完整剧本（统计 + 门② + 标题梗概卡 +
  分集表 + 返工）、集（集标题卡 + 场次表）、场（只读芯片 + 阅读/编辑切换 + 贴底保存条）。
  窄屏时视图标题块排到按钮行下面独占一行（`max-sm:order-last basis-full`），
  不和「目录」「改动记录」挤成一条缝。
- **阅读优先**：默认是 `.ff-paper` 纸面排版；进入编辑后每个字段一个输入，
  改过的字段标「已改」（字段名旁的暖色小字 + 边框色），不堆整页表单。
  `label` 只包字段名，不包输入框——包住 textarea 会把正文算进可访问名称。
- **只读就说只读**：集号、场号、`node_coverage` 用只读芯片显示；老产出缺的字段
  禁用并说明「这份旧产出没有这个字段」，不提交不存在的路径。
- **未保存保护**：页内切换走确认弹窗；站内链接与浏览器后退走
  `use-navigation-guard`；整页卸载走 `beforeunload`。dirty 或保存中时，门、返工、
  撤销、顶栏「推进生产」全部禁用，并在 `title` / 说明里写清原因。
- 不放生成图片按钮：剧本没有出图能力，放了就是假入口。

### 角色/场景工作台（P2B，`/freeflow/projects/[id]/characters`、`/scenes`）

与分镜、剧本同一个壳：紧凑顶栏 + 模块栏 + 对象目录 + 主区，本页**不画**胶片连续带和右栏。

- **左目录 264px**（`.ff-sb-directory`）：标题 + 真实计数「N 个 · 有图 M」→ 搜索
  （角色：名称/身份/ref；场景：名称/时段/环境/ref）→ 「全部X（总览）」→ 按数组顺序列出的对象，
  每行名称 + ref + 出图状态图标（已有图 / 图可能过期 / 生成中 / 上次失败 / 未出图）。
  搜索只筛显示、不导航；正在编辑的对象钉在目录里并标「未保存」。写库中目录按钮
  **禁用**并在搜索框下写「正在写回改动，完成后才能切换」，不是点了没反应。
  窄于 `lg` 收成「目录」按钮 + 左侧抽屉 `min(390px, 100vw − 3.5rem)`，选中即关。
- **总览**：计数行（个数 / 有图 / 可能过期 / 生成中 / 失败 / 未出图，场景另加时代与整体色调）
  → 场景页的门③ → 卡片网格（角色 3:4、场景 1:1，`object-contain`）→ 自然语言返工。
- **单个对象**：头部（目录 · 全部X · 名称 + ref · 第 n / N 个（搜索内）· 改动记录 · 上/下一个）；
  `xl`（1280）起大图与档案左右各半，窄于 `xl` 纵向，大图在上。大图完整显示（`contain`），
  角色 3:4、场景四视图 1:1，下面是出图记录缩略图，点开看历史版本。
- **身份是数组位置**：URL 用 `?ref=`，只有 ref 重复时才加 `&at=`。补丁一律打在原数组位置，
  与搜索结果里的序号无关。`ref`、推断字段、旧 `build`、光照**名称**只读，用芯片展示。
- **只读就说只读**：旧档案缺的键、受控词表外的值、会被后端规范化丢项的列表（空项、光照重名）
  都显示成虚线框里的当前值 + 「只读」+ 原因，不提交不存在的路径。只读项的字段名是普通文字，
  不用指向非表单元素的 `label`。
- **出图动作复用现成件**：平台 / 本机、查看 / 准备提示词、生成 / 重试、用已有图（资产库 / 本地上传）。
  dirty 或保存中四类动作全部禁用，大图下方写原因；保存成功后旧的准备词作废，
  旧图标「可能过期」，**不自动重出**。切对象以 `ref:at` 为 key 重建，图、词、错误都不串。
- **门③** 只在场景总览出现，一次确认全部场景的锚点与光照；对象视图里只放一条提示和
  「去总览确认」。搜索和选中对象不改变审核范围。
- **未保存保护**沿用 P2A：页内切换走确认弹窗，站内链接与后退走 `use-navigation-guard`，
  整页卸载走 `beforeunload`；dirty 或保存中时撤销、顶栏「推进生产」禁用并写明原因。
  库值变化（保存、撤销、返工）时草稿逐字段跟上：没动过的字段换新值，动过的保留。

### 首页与资产（P3A，`/freeflow`、`/freeflow/projects`、`/freeflow/assets`、`/freeflow/projects/[id]/assets`）

沿用全局两级导航与暖黑金 token，不另起一套。

- **两个动作必须分得开**（`StartComposer`）：「开始生产」是主按钮，要项目名 + 原文；
  「只创建项目」是次按钮，只要项目名。按钮旁常驻两行说明各自做什么：只创建不保存原文、不调用模型；
  开始生产会调用模型、扣 Credits。原文框下写明「只在开始生产时提交，之前只在这一页」，
  有原文时 `beforeunload` 与站内导航都要确认。**不要**做成一个「创建」按钮再在后面悄悄跑模型。
- **开始生产先确认**：确认框列出项目名、原文字数、「会跑到第一道审核门为止」、按实际用量扣 Credits、
  当前余额（读不到就写读不到）。确认前不发任何请求；确认后 create 与 advance 分两步，进度分两步写。
  advance 失败时项目名锁定并标「已创建」，按钮变「重试开始生产」，重试只发 advance，不重复建项目。
- **时间字段只用一种**：近期项目按 `updated_at` 倒序，标题旁写「按最近编辑」，卡片写「最近编辑 …」。
  不拿 `created_at` 兜底，也不在同一列表里混用「创建时间」。
- **资产范围先说清**：全局页范围下拉「全部项目 / 某个项目」，旁边一句话说明各自包含什么
  （独立角色档案不属于任何项目，选了项目就不出现）。项目内资产页范围固定，给「去资产库看全部」。
  上传按钮按范围命名：「上传到资产库」（不挂项目）/ 全局页选了项目时「上传到「项目名」」/ 项目内「上传到本项目」。
- **类型筛选只用真实类型**（单选芯片）：全部 / 图片 / 视频 / 音频 / 文本 / 文档 / JSON / 角色档案 / 场景档案 /
  Skill（仅全局）。不画文件夹、标签、使用次数，后端没有这些字段。
- **搜索只覆盖已载入的部分时要说出来**：有下一页时列表底部写「已载入 N 个文件，还有更早的」，
  搜索中再补一句「搜索只覆盖已载入的部分」，旁边是「加载更多」。
- **预览**用右侧抽屉（`Dialog`）：图 `contain`、视频/音频原生控件、文本读前段并标截断，
  其余文件只写「不能在页面里预览」+ 下载。档案详情写明「项目档案，最近一次生成的版本」并给「在项目中打开」（工作台里之后的手改以项目为准）。
- **上传失败按阶段说**：创建上传 / 文件传输 / 完成登记，多选时写明前面几个已成功。
- 接口响应缺列表字段时当空列表（`normalizeLibrary`），只让该区域为空，不让整页抛错。

### 任务与设置（P3B，`/freeflow/projects/[id]/tasks`、`/freeflow/tasks`、`/freeflow/projects/[id]/settings`）

沿用全局两级导航与暖黑金 token。模型 / 供应商 / 项目模型覆盖不在这一轮，见下一节「模型与供应商（ADR-039 A2）」。

- **两种语义分开**：项目任务页两个视图「生成记录」（回看创作过程：文本步骤 + 出图各自的输入、提示词、结果）
  与「执行队列」（`tasks` 表：进度、失败原因、重试 / 取消），各写一行说明。视图与定位写进 URL
  （`?view=queue&task=`、`?view=records&record_type=&record_id=`），刷新保持、可被链接。模块栏与顶栏都叫「任务」。
- **状态只认 `tasks.status`**：出图类生成记录的状态用任务快照覆盖，不在前端另算。筛选芯片：全部 / 进行中 / 已完成 /
  失败 / 已取消（失败与已取消分开：一个能重试一个不能），条数只覆盖已载入的部分，有下一页时写出来。
- **账本一行**（`TaskLedger`，`.ff-ledger`）：对象链接（角色 / 场景 `?ref=`、镜头 `?shot=`）+ 任务类型 + 第 N 次尝试 +
  （全局页）所属项目 + 时间 + 成本 + 「生成记录」链接；失败行左侧红竖边，写中文原因 + 原码；不可重试的写「这类失败不能直接重试」
  并指到对象。缺字段的旧任务写「时间未记录」「没有记录失败原因」，不报错。`?task=` 命中的行 `aria-current` + `data-flag=review`。
- **恢复动作只给接口允许的**：取消只给 queued / running；重试只给 failed 且错误码不在后端登记的不可重试表里（前端镜像表由单测对照
  `core/errors.py` 锁定）。都要确认框：重试写「重新预扣 N Credits」「沿用当时的输入，不用之后改过的设定」；取消写「不能再重试」
  「预扣退回」，两个按钮不同名（「保留任务」/「取消这个任务」）。失败时弹窗不关、显示后端原文。**不做批量动作**（没有接口）。
- **实时**：项目页走项目 SSE，旁边常驻连接状态（实时更新中 / 断开正在重连）。重连后重取快照补齐断线期间的变化；
  动作后的重拉不被通道里更早的快照盖回。全局页没有组织级事件流，写明「这一页不实时更新」，回到页面时与「刷新」重取。
- **全局任务页范围**：所有项目的执行任务，文本步骤不进队列（写明去项目的生成记录看）；项目下拉走服务端 `project_id`；
  拿不到的项目写「项目不可见或已删除」，无项目写「不属于任何项目」；项目名链到该项目执行队列的那一行。
- **设置（与模型无关）保存成功才更新显示**：项目名称、锁定变量改了未存时写「未保存。当前：…」；失败保留草稿与原值并显示后端原文
  （含字段原因）；成功后顶栏跟着换名。`/freeflow/settings` 仍是占位（没有与模型无关的全局设置），不套账本。

### 模型与供应商（ADR-039 A2，`/freeflow/models`、项目设置的模型覆盖）

沿用全局两级导航、暖黑金 token 与 `.ff-ledger` 账本，最大宽 880。参照「添加供应商 → 填 Key → 一键设为默认」。

- **两本账分开**：上面是「默认模型」，每个已接入能力（文本、出图）一本，账头写「当前：连接 · 模型」或「平台 · 某家」，
  平台目录的一家一行（模型下拉 + 计费来源），供应商的「连接 × 该能力的模型」一行一个「设为默认」，当前那行写「当前默认」不给按钮；
  下面是「供应商（N / 上限）」，每行名称、来源（预设 X / 自定义）、Base URL、掩码 Key、启用状态、模型及能力，
  动作只有「测试连接 / 编辑 / 停用（启用）/ 删除」。账式行的「在用」语义不变。
- **切换默认保存成功才换**：一次点击一次 `PUT`，以响应为准；失败本行保持原值，账内显示后端原文。
  组织默认失效（`broken_reason`）时账头下一条 `data-flag=danger` 横幅写人话原因，下面各行照常可点、直接改选，不自动换到别家。
- **添加 / 编辑用右侧抽屉**：先选来源（预设或「自定义」）；选了预设，表单顶上给「去 X 取 Key」链接，没有就给该家文档链接，只需填 Key，
  地址与模型已带出可改；自定义填名称、Base URL、Key、模型 id + 协议（协议只从后端白名单选，能力随协议只读显示）。
  保存失败抽屉不关、草稿保留、显示后端原文。
- **Key 只在输入框里出现**：`type=password`、`autoComplete=off`，可切显示；编辑时为空，占位写「已保存 掩码，留空不更换」，
  只发改过的字段，Key 为空不发。列表只显示后端给的掩码，前端不拼、不缓存明文。
- **测试连接三态**：通过（绿）/ 无法免费验证（琥珀，**不是**失败）/ 失败（红 + 后端原文）。已保存连接走 `/{id}/test`，不从前端发 Key。
- **删除先说后果**：确认框先读引用，列出哪些组织默认、哪些项目正指向它，写明「删除后这些地方生成时会报错，不会自动换到别的供应商或平台」；
  读不到引用就照实写，仍允许删除（后端不阻止）。按钮「删除 / 保留」。停用、启用同样成功才变。
- **诚实标注**：第三方出图模型 `consistency_verified=false` 标「画风一致性未实测」；模型行可勾「推理模型」，
  旁注「流程中的分类、结构化环节不能用推理模型」，列表与默认候选都带这个标记。视频 / 语音只写「M2 待办」与后端原因，不给控件。
- **项目覆盖与组织默认分清**：项目设置的模型区块写明「项目覆盖：只改本项目，不选就跟随组织默认」并链到模型页；
  下拉分组「平台模型 / 我的供应商」，第一项「跟随组织默认（当前是谁）」，组织默认失效时这一项也说出来。
  已存值找不到对应连接时补一个「已失效的设置（请改选）」选项，不让下拉静默显示成别的值。
- **报错给原文**：`provider.byok.rejected` 按 `detail.reason`（连接不存在 / 已停用 / 模型不存在 / 推理模型不能用在这一步）
  翻成人话，出图失败与项目设置保存失败共用这一套。

## 6. 动效

档位 2/10（Subtle）。

```
状态切换   150ms  ease-out
面板展开   200ms  ease-out
骨架屏     不做花哨的 shimmer，静态占位即可
```

**不引入 GSAP**，不引入任何动画库。

本轮删掉了两处默认动效：每张卡 hover 上浮、卡内图片 hover 放大。
"每张卡都会动"是模板感的来源，不是精致的来源。
保留的只有 `animate-pulse-soft`（生成中）——它对应一个真实的进行态。

`prefers-reduced-motion: reduce` 一律降级到无动画。

## 8. 反模式

- ❌ 随意混用扁平与拟物
- ❌ emoji 当图标
- ❌ 组件里写死调色板类名
- ❌ 只在 `:root` 定义颜色而不给 `.dark` 配套
- ❌ **给工作台加 hero 区**
- ❌ **带色调的页面底色**——会干扰用户对生成画面的颜色判断
- ❌ **同尺寸卡片墙**：所有内容切成一样大的圆角卡，靠阴影分层
- ❌ **全大写 + 大字距的 eyebrow 标签**
- ❌ **`A · B · C` 中间点串接的 meta**
- ❌ **每张卡 hover 上浮 / 每个区块入场淡入上滑**
- ❌ **标题里只给一个词换色**
- ❌ **渐变填空**、霓虹光晕、装饰性噪点
- ❌ **把齿孔/刻度线铺满全站**——纹理铺满就不再是标志
- ❌ 只换一套暗色就当完成重塑：身份必须来自信息结构和页面节奏
