## 0. 产品定位（决定一切设计判断）

```
产品类型   内部生产工具 / 工作台（不是营销站，不是内容消费站）
主角       用户生成的图片和视频
用户       创作者，长时间连续使用，一次盯 60 个镜头
使用场景   桌面为主，高密度，键盘友好
```

**第一原则：界面必须退到画面后面。**
UI 的任何颜色都不能干扰用户对生成画面的判断——这直接排除了带色底、
高饱和边框、大面积品牌色。调色台的墙是中性灰，就是这个道理。

## 2. 颜色

中性色走 slate 色阶（蓝偏中性，不是纯灰——纯灰看起来像没选过）。
所有值用 OKLCH，符合 shadcn 主题规范。

### 角色分配

| 角色 | 亮色 | 暗色 | 用途 |
|---|---|---|---|
| `background` | slate-50 | slate-900 | 页面底 |
| `surface` | white | slate-850 | 卡片、面板 |
| `surface-2` | slate-100 | slate-800 | 嵌套面板、输入框底 |
| `border` | slate-200 | slate-700 | 分隔线、描边 |
| `foreground` | slate-900 | slate-50 | 正文 |
| `muted` | slate-500 | slate-400 | 次要文字、标签 |
| `primary` | teal-600 | teal-400 | 交互元素、选中态、焦点环 |

### 语义色（与主色分离，不复用）

| 角色 | 亮 / 暗 | 用途 |
|---|---|---|
| `running` | amber-600 / amber-400 | **仅**用于"生成中 / 渲染中" |
| `success` | green-600 / green-500 | 完成、通过 |
| `danger` | red-600 / red-400 | 失败、超预算、删除 |

**为什么 amber 单独占一个角色**：这个产品里"正在生成"是最高频、
最需要一眼识别的状态——一屏 60 个镜头，用户要立刻看出哪些在跑。
把它从普通 warning 里拎出来，是信息设计决策，不是配色偏好。

**为什么 teal 主色和 green 成功色能共存**：色相差约 33°，且状态一律
「图标 + 文字 + 颜色」三重编码，不靠颜色单独传达含义
（对应 skill 优先级表第 10 条）。

### 2.1 对比度实测与修正（2026-08-16）

在浏览器里用 canvas 解析 OKLCH 后逐对实测，**发现检索给的 600 系颜色
在亮色模式下全部不达标**：

| 项 | 修正前 | 修正后 | 处理 |
|---|---|---|---|
| primary / 白底 | 3.74 ✗ | **5.47** | teal-600 → teal-700 |
| running / 白底 | 3.19 ✗ | **5.02** | amber-600 → amber-700 |
| success / 白底 | 3.30 ✗ | **5.02** | green-600 → green-700 |
| danger / 白底 | 4.83 | **6.47** | red-600 → red-700 |
| subtle / 面2（亮） | 4.34 ✗ | **5.65** | slate-500 → 深一档 |
| subtle / 面2（暗） | 3.07 ✗ | **5.18** | slate-500 → 亮一档 |
| 各软底药丸文字 | 2.8–3.3 ✗ | **4.54–5.66** | 软底整体调淡 |

暗色模式的 600 系本来就够（主色 8.74、running 9.75），只有 subtle 需要提亮。

**当前状态：两主题共 26 项配对，全部 ≥ 4.5:1，最低 4.54。**

> 教训记录：`getComputedStyle` 现在原样返回 `oklch(...)` 字符串。
> 用正则当 RGB 解析会得到完全错误的对比度数字（第一次测出来正文只有 1.1）。
> 必须用 canvas `fillStyle` + `getImageData` 让浏览器真实解析。
> 复测脚本见本目录 `contrast-check.js`。

## 3. 字体

```
拉丁 / 数字   Plus Jakarta Sans      ← DB 命中
中文          系统栈（PingFang SC / 微软雅黑 / Noto Sans SC）
等宽          ui-monospace 系统栈
```

**中文不用 Web 字体**：中文字体动辄数 MB，对一个每天要开一整天的
工作台是净负担。个性从密度和布局出，不从字体出。

**数字一律 `font-variant-numeric: tabular-nums`**：
时间码、镜号、Credits、时长、成本——这些都要按列对齐。
生产工具里数字跳动是硬伤。

### 字号阶

```
xs   12px / 16   标签、元数据、表格次要列
sm   13px / 18   正文默认（工作台密度）
base 14px / 20   表单、按钮
lg   16px / 24   区块标题
xl   20px / 28   页面标题
2xl  24px / 32   仅用于空状态和登录页
```

正文 13px 低于 skill 建议的 16px 基准。**这是有意偏离**：
高密度工作台的行业惯例（Linear / Figma / DaVinci 均在 12–13px），
用户是长时间专注使用的专业用户而非偶尔到访的访客。
代价是必须把对比度拉满补偿——正文对比度 ≥ 7:1，超出 WCAG AA 要求。

## 4. 间距与圆角

密度档位 9/10（Dense / Dashboard）。

```
间距阶   4 / 8 / 12 / 16 / 24 / 32 / 48
圆角     sm 4px   md 6px   lg 8px   full 9999px
```

**不用 `rounded-lg` 当默认**（skill 反模式清单里点名了）。
默认 4–6px，只有头像和状态药丸用 full。

## 5. 布局

```
┌──────┬───────────────────────────────────────┐
│      │  顶栏：项目上下文 · 阶段进度 · Credits │
│ 导航 ├───────────────────────────────────────┤
│ 轨   │                                       │
│      │  主工作区                              │
│ 56px │  镜头/角色 = 接触印相表式网格           │
│ 或   │  图占满，信息压成底部一条细说明带        │
│ 200px│                                       │
└──────┴───────────────────────────────────────┘
```

- 左轨可折叠（56px 图标态 / 200px 展开态）
- 顶栏常驻项目上下文——用户在 60 个镜头里穿梭时必须知道自己在哪
- 内容网格 `minmax(180px, 1fr)`，自适应列数

## 6. 动效

档位 2/10（Subtle）。

```
状态切换   150ms  ease-out
面板展开   200ms  ease-out
骨架屏     不做花哨的 shimmer，静态占位即可
```

**不引入 GSAP**。检索给了 ScrollTrigger 预设，但那是给营销页滚动叙事用的，
工作台没有滚动叙事。多余的动画只会让长时间使用的用户烦躁。

`prefers-reduced-motion: reduce` 一律降级到无动画。

## 7. 交付前检查清单

来自 skill 的 Pre-Delivery Checklist，加了本项目特有的两条：

- [ ] 不用 emoji 当图标（用 Lucide SVG）
- [ ] 所有可点元素有 `cursor-pointer`
- [ ] hover 过渡 150–300ms
- [ ] 文字对比度 ≥ 4.5:1（本项目正文要求 ≥ 7:1，见 §3）
- [ ] 键盘焦点态可见
- [ ] 尊重 `prefers-reduced-motion`
- [ ] 响应式 375 / 768 / 1024 / 1440
- [ ] 组件里不出现写死的颜色值，一律走 token
- [ ] **状态不靠颜色单独传达**（图标 + 文字 + 颜色三重编码）
- [ ] **所有数字列用 tabular-nums**

## 8. 反模式

skill 清单 + 本项目补充：

- ❌ 随意混用扁平与拟物
- ❌ emoji 当图标
- ❌ 组件里写死 `bg-teal-600` 这类调色板类名
- ❌ 只在 `:root` 定义颜色而不给 `.dark` 配套
