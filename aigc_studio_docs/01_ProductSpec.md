# AIGC Studio 产品需求文档（PRD）

## 1. 用户类型

### 普通创作者
目标：低门槛完成视频/漫剧。

### 半专业创作者
目标：控制角色、风格、镜头和模型选择。

### 专业用户
目标：使用自定义 Skill、ComfyUI Workflow、本地 GPU、远程节点。

### 平台管理员
目标：模型供应商、节点、价格、任务、用户、审核、财务。

## 2. 首页核心入口

核心输入框：

> “你想做什么？”

示例：

- 把这篇小说做成 5 分钟悬疑漫剧
- 给我做一个产品宣传视频
- 把这张人物立绘做成 8 秒动作镜头
- 把下面文章做成 3 分钟知识解说视频

用户提交后进入 Router Agent。

## 3. Router Agent 产品逻辑

Router Agent 是用户需求进入系统后的第一道入口。

输入：自然语言 + 附件 + 用户偏好 + 历史项目上下文。

输出：

- 内容类型
- 推荐路线
- 推荐 Skill
- 推荐 Director
- 预计复杂度
- 预计成本区间
- 是否需要用户补充信息

初始路线：

```text
NOVEL_TO_ANIME
SCRIPT_TO_VIDEO
IMAGE_TO_VIDEO
VIDEO_EXPLAINER
PRODUCT_VIDEO
SHORT_VIDEO
CUSTOM
```

Router 只负责“分类与路由”，不要承担具体生产任务。

## 4. Director Agent

Director 是整个创作项目的“总导演/项目经理”。

职责：

1. 读取 Router 输出
2. 选择或推荐 Skill
3. 制定阶段计划
4. 决定需要哪些专业 Agent
5. 决定模型能力需求
6. 判断哪些步骤需要人工确认
7. 管理重试与返工
8. 维护生产状态
9. 对结果做质量检查
10. 最终交付

Director 不直接生成所有内容，而是调度 Agent + Tools。

## 5. 审核门槛

> 2026-08-16 修订：原方案默认 9 道确认门。真实用户会在第 4 道关掉页面。
> 改为**默认 3 道**，其余降级为"可展开查看，不阻塞"。

### 默认（标准模式）——只有 3 道阻塞门

```text
Gate A  设定确认    故事结构 + 角色基准立绘 + 场景
                    ★ 角色基准立绘是最关键的一道，
                      在这里多花 30 秒，能避免后面 60 个镜头全部报废
Gate B  分镜确认    剧本 + 分镜 + 预览档视频
                    ★ 确认后才进入定稿档渲染（见 ADR-015）
Gate C  成片确认    最终交付
```

其余环节（路线、世界观、单镜头提示词、关键视觉）**默认自动通过**，
但在工作台中随时可查看和干预。

### 可选模式

| 模式 | 行为 | 适用 |
|---|---|---|
| 严格 | 展开为 9 道门 | 专业用户，对成片要求高 |
| 标准 | 3 道门（默认） | 绝大多数用户 |
| 自动 | 仅异常与超预算时停顿 | 批量生产 |

**设计原则**：门的数量与用户专业度正相关，与流失率正相关。
默认值必须偏向少门。

## 6. MVP 页面

> 原方案 14 个页面。M1 只做 7 个。

**M1（7 个）**

1. 登录 / 注册
2. Dashboard（项目列表 + 余额 + 进行中任务）
3. 创作工作台（含 Agent 对话与运行状态，**吸收原 Agent 运行面板**）
4. 角色与场景管理（**合并**，一致性资产在这里确认）
5. 分镜管理
6. 资产库
7. Credits 与账单

**M2 追加**：时间线预览与成片页

**M3 追加**：运营后台（用户 / 订单 / 任务 / 成本看板）

**M4 追加**：节点与服务器、Skill 库

## 7. MVP 不做

- 社交社区
- Marketplace 交易系统
- 完整视频编辑器（只做时间线预览 + 有限调整）
- 多租户企业组织体系（但**数据库层面预留 `org_id`**，见 `09_Database.md`）
- 复杂计费订阅（只做 Credits 充值）
- 大规模推荐系统
- 云 GPU 租赁（方案预留，见 `07_AutoDL.md`）
- Public API

## 8. 免费额度与转化

见 `19_UnitEconomics.md` 第 5 节。核心约束：

```text
免费：到分镜脚本为止（成本 ≈ ¥3，纯 LLM）+ 1 个镜头试片（≈ ¥2）
付费：任何批量视觉生成
```

**这是产品设计约束，不只是运营策略**：
分镜脚本必须做得足够好看、信息足够完整，它是免费到付费的唯一转化点。
