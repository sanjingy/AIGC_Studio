# 第一里程碑：真正可运行的纵向切片

> **这是第一个里程碑，没有前置条件，可以直接开工。**
>
> 技术验证以**内嵌切片**的形式放在 M1 中段（能真实出图之后立即做，
> 2–3 天，10 个镜头），不作为开工前的阻塞项。见 `12_MVP_Roadmap.md` 与 ADR-016。

## 目标

先不要追求“很多模型”。

要完成一条完整链路：

```text
用户
 ↓
创建项目
 ↓
输入一句创作需求
 ↓
Router Agent
 ↓
Director Agent
 ↓
Story Agent
 ↓
人工确认
 ↓
Character Agent
 ↓
人工确认
 ↓
Storyboard Agent
 ↓
人工确认
 ↓
Mock Image Provider
 ↓
Asset Library
 ↓
Mock Video Provider
 ↓
最终视频 Asset
```

## 完成标准

用户可以在浏览器里完整操作一次，并且：

- 页面状态实时变化
- Agent 状态可视化
- 每步可确认
- 可修改
- 可重试
- 可取消
- 任务失败可恢复
- 所有结果进入资产库
- 所有过程可追踪
- Credits 能正确 reserve/settle/release

## 为什么先做这个

这条纵向切片可以验证产品最核心的风险：

> “Agent 自动制片 + 人工确认 + 异步生成”是否真的能跑通。

当这条主链跑通后，再不断增加真实模型、ComfyUI、GPU 和 Skill。

## 两类风险与验证时机

M1 同时承载两类性质不同的风险：

| | 内容风险 | 工程风险 |
|---|---|---|
| 问题 | **AI 能不能做出可用的画面** | **系统能不能自动化这个过程** |
| 验证方式 | M1 中段的 10 镜验证切片 | M1 整体交付 |
| 失败意味着 | 一致性策略要升级（L1→L2） | 工程实现要调整 |

架构先行的决定（ADR-016）意味着内容风险的验证被推后。
**对冲手段是把可能被推翻的部分都做成可替换模块**——
一致性策略、废片率参数、镜头时长模型、后处理链，
四处都不写死（见 `12_MVP_Roadmap.md` 开头的对冲表）。

> 验证切片一旦能做就立刻做，不要拖到 M1 结束。
> 越早拿到真实废片率，成本模型和 Provider 选型的决策就越准。

## M1 不使用 Mock 的部分

`13_CodexDevelopmentGuide.md` 要求 Mock First，但有两处例外——
**图像生成和一致性必须用真实模型**：

- Mock 出图无法验证一致性，而一致性是本项目核心风险
- Mock 出图无法测出真实废片率，成本模型就无法校准

其余（视频、ComfyUI、云 GPU）在 M1 全部用 Mock。
