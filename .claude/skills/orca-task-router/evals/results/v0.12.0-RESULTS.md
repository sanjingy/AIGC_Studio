# orca-task-router v0.12.0 测试结果

跑法按 skill-creator 的 Running and evaluating test cases：21 条用例各起 with_skill 和
without_skill 两个 subagent，产出交给读 `agents/grader.md` 的评分 agent 逐条判 expectations，
再用官方 `scripts.aggregate_benchmark` 汇总。冒烟和一致性校验是本 Skill 自带的，一并跑成并集。

## 这个数字不能直接当"Skill 的价值"用

多个评分 agent 各自独立指出同一件事：without_skill 不是干净基线。
用户全局规则 `~/.claude-profiles/20x/rules/orca-task-routing.md` 是本 Skill 规则的压缩版，
每个会话都会加载，对照组照样拿得到模型档位、`[1m]` 后缀、Fable 闸门、验收权归属这些结论。
8 条零区分度用例里，评分 agent 逐条追到了这份记忆的对应行。

所以这轮真正测出来的是 **Skill 相对于自己那份压缩规则的增量**，不是相对于零。
增量落在记忆没写的地方：full handoff 的排除时机、Orca 状态机的不可逆点、
`worker-start --worktree`、`--retry-of` 的拒绝条件、`wait --for tui-idle`。

## 评分 agent 提的断言质量问题

按 grader.md 第 4 步，评分 agent 除了打分还要批评断言本身。反复出现三类：

1. **反向断言奖励无知**。`没有用--retry-of` 这类断言，对照组因为压根不知道这个参数存在而白拿分。
   #18 的评分 agent 明说 without_skill 的 3/7 里有 2 分是这么来的，按实际掌握程度只值 1/7。
2. **断言查的东西全局记忆里已有**。#4、#10、#20 三条整条用例的答案都能在 `orca-task-routing.md` 里逐字找到。
3. **没有任何断言在查命令真不真**。这是最值钱的缺口。多个 without_skill arm 编出了
   `orca terminal open --tier ultra`、`orca team spawn`、`orca task create --brief`、
   `claude-fable-1[1m]` 这类不存在的命令和模型号，方案完全不可执行，照样拿高分。
   加一条"启动命令必须能在 `orca --help` 里找到"的断言，区分度会立刻上来。

三点都记在 `_grading/*.critique.md` 里，逐条有原文证据。下一轮改断言集时从这里起。

## 工具链上遇到的两个坑

- 官方 aggregator 读的是 `grading.json` 里的 `summary.{passed,failed,total,pass_rate}`，
  而 skill-creator 的 SKILL.md 正文只说了 `expectations` 要用 `text`/`passed`/`evidence` 三字段，
  `summary` 块只在 `aggregate_benchmark.py` 的代码里出现。按正文写会得到 0.0% 且不报错。
- 官方布局把 `eval_metadata.json` 放在用例目录下，前提是 runner 由 `run_eval.py` 起、
  拿不到那个目录。用 Agent 工具手起 runner 时这个前提不成立，答案会泄漏。
  作废的那一轮记在 `../iteration-2/VOID.md`。
