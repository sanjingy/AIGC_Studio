## 一、总体判断

文档质量在同类项目里属上游：领域拆分清晰、ADR 意识、Mock First、
Definition of Done 都很扎实。**问题不在于架构不好，而在于：**

> 它设计的是一个 D 轮公司的系统，
> 而且**把最难的东西漏了，把最不该现在做的东西写满了**。

按原蓝图完整实现，估算 8–15 人年。

**三个最严重的问题：**

1. **一致性缺失** —— 漫剧最难的技术点（角色不变脸），
   在原文档中只在"长期扩展方向"里出现过一次。本末倒置。
2. **成本模型缺失** —— 通篇没有算过一部片子多少钱。
   Router 示例中的 `estimated_credit_range: [2000, 5000]` 低估了 6–15 倍。
3. **四套状态机并存** —— LangGraph checkpoint / `tasks` / `agent_runs` / 队列，
   必然导致状态互相矛盾。

## 三、核心结论（供决策）

### 3.1 成本结构（`19_UnitEconomics.md` 详版）

一部 5 分钟漫剧，60 个镜头：

| 档位 | 成本 | 视频占比 | 图片占比 | LLM 占比 |
|---|---|---|---|---|
| 经济档 | ¥50 | 90% | 1% | 3% |
| 标准档 | ¥150 | 62% | 33% | 2% |
| 高质档 | ¥355 | 81% | 14% | 2% |

**三条硬结论：**

1. LLM 成本占 2–3%，可忽略。不要为省 token 阉割 Router/Director 上下文。
2. 成本 100% 集中在**视觉产物的废片率**。一致性引擎是**成本中心**，不是功能。
3. 分级渲染省 35–60%，是本次评审性价比最高的一条改动。

**盈亏平衡：每天 16 部成片**（标准档，2 人团队）。
这是最应该贴在墙上的数字，所有功能优先级都用它来排。

### 3.2 建议砍掉的

已在文档中标注为预留/暂缓：

- 云 GPU 租赁 / AutoDL（**按要求保留文档与接口，不排期**）
- 7 微服务 → 1 单体
- Agent 11 → 4
- Human Gate 9 → 3
- MVP 页面 14 → 7
- 入站 SSH（**彻底删除**，避免不可回收的安全债）
- Public API 路由预留
- Skill / Workflow / GPU Marketplace

### 3.3 关于验证时机（建议 → 决策）

**评审建议**：在写第一行平台代码之前，花 2 周用现成工具手工做出一部
3 分钟漫剧（M0），回答文档 2000 行都没回答的问题——
参考图相似度、图生视频漂移、哪种镜头最容易崩、**真实废片率是多少**。

**用户决策（2026-08-16）**：不采用 M0 作为前置项，
**先做整体架构，之后做一次简单验证**。已记入 ADR-016。

**已按此决策调整：**

- `12_MVP_Roadmap.md` 删除 M0，关键路径改为 M1 → M2 → M3
- 技术验证改为 **M1 中段内嵌的 10 镜验证切片**（2–3 天），
  触发点是"AI Gateway 打通、能真实出图"，不等 M1 完成
- LoRA 相关问题推到 M4（依赖 GPU Runtime，M1 阶段答不了也用不上）

**代价与对冲（ADR-016 已记录）：**

| 假设 | 未验证的风险 | 架构对冲 |
|---|---|---|
| 一致性 L1 够用 | 可能必须上 L2 | L0–L4 可插拔策略，共享统一接口 |
| 废片率 2.5 / 1.5 | 可能差一倍 | 走 `pricing_rules` 热更新，改数不改码 |
| 5s 一镜、60 镜 | 镜头可能更碎 | 时间线不假设固定镜头时长 |
| 图生视频漂移可控 | 可能需额外后处理 | 生成与后处理分离，可插 L3 |

**一条硬约束**：可观测性不可推后。一致性度量指标必须先于一致性策略实现，
`resolved_prompt` 与中间产物第一天就落库——否则验证切片跑完也拿不到结论。

**当前状态**：`19_UnitEconomics.md` 的成本数字在废片率回填前属于估算，
**不可用于对外报价**。
