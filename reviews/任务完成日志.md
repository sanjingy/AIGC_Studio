## 2026-08-19 · 修复中文人名导致角色阶段卡死

**问题**：上一轮出图任务真机测试发现的既有 bug——`visual.character.v1`
遇到中文/日文/生僻字人名（如"绯色冴子"）会直接把原名当 `ref` 输出，撞
`^[a-z][a-z0-9_]{1,30}$` 校验；根因还有一层：`complete_structured()` 重试
时不把上次的校验错误告诉模型，导致三次重试全输出同一个错误答案。三次
全废后 `advance()` 直接 500，项目卡死在角色阶段。

**做了什么**：提示词补齐 `ref` 起法说明（罗马化优先，罗马化不了退回
`char_N`）；`CharacterSheets` 加 `model_validator(mode="before")` 兜底——
非法 ref 在字段校验前改写成合法值，不再让整份角色档案校验失败。兜底后缀
**取人名哈希而不是位置下标**：位置下标跨次重跑不稳定（同一人物这次排
第 2 位下次第 3 位），会被一致性引擎误判成新角色、产生两份 `CharacterProfile`
且旧的那份被覆盖——这是我在任务书里要求它自己判断的风险点，它验证后
确认会发生，主动选了哈希方案堵死。

**执行**：Opus 5 `high` Terminal Worker，独立任务，约 25 分钟。

**我复核的结果**：`pytest -q` exit 0（560 例）、`ruff check`/`mypy` 全过；
读了 `agents/schemas.py` 的 `_rescue_refs`/`fallback_character_ref` 实现，
批内去重、日志记录、稳定哈希后缀均符合预期。

**顺带发现、未修（已记录，未派发）**：
1. `visual_scene.yaml` 同样从未解释 `ref` 格式，场景名天然是中文，角色
   阶段这次通了之后，**场景阶段大概率立刻复现同一个 500**——这个优先级
   应该很高，建议尽快开一个同形状的任务。
2. `orchestrator.py:491` 让角色 Agent"用剧本里已有的 `character_ref`"，
   但 `Beat.character_ref` 没有格式约束，与新规则潜在冲突。
3. `runner.complete_structured()` 重试不带纠错反馈——这是更系统性的根因，
   影响所有 Agent，任务书里明确排除本次做，建议单开任务评估。

## 2026-08-19 · 出图接上界面（角色立绘 / 分镜出图）

**问题**：`worker/jobs/generation.py` 能出图、`consistency/compose.py` 能合成
提示词，但正常项目流程从来没把两者接起来过——`style_profiles`/
`character_profiles` 两张表只有验证脚本手工写过，M1 的验收标准"用户能在

**做了什么**：编排器 `advance()` 跑完角色阶段后自动同步一致性引擎；新增
`/projects/{id}/images` 三个端点（角色立绘、分镜出图、列表），提示词一律
由 `compose` 合成，走正常任务预扣/结算路径；前端角色卡片和分镜表加生成
入口 + 进度 + 结果图。

**执行**：Opus 5 `high` Terminal Worker，独立任务，约 1 小时。

**我复核的结果**：`pytest -q` exit 0（546 例）、`ruff check`/`format --check`/
`mypy` 全过、`npm run build` 9 路由全过；抽读了 `render.py`/`orchestrator.py`
关键改动，404-not-403、幂等同步、`rollback()` 处理、`attempt+1` 计费对齐
均符合项目规则。Worker 自己的真机验证（真实生成两张图、跨租户 404、

**未完成项**：浏览器点击验收未做（Chrome 扩展未连接会话）。

## 2026-08-19 · Gateway BYOK 接线（补财务漏洞）

**问题**：BYOK 计费按折扣算了，但 Gateway 实际出图/调模型仍然用平台自己的
Key——用户配了自己的 Key、按折扣付了钱，实际花的却是平台的钱，差额平台
承担且不报错。这是我自己读 `gateway/service.py` 时发现并标记为最高优先级
的问题。

**做了什么**：Gateway 改为按调用时的 `org_id`+能力实时解析 Key（不再是
进程启动时读一次环境变量的单例），熔断器按账号维度隔离，BYOK 失败不回退
平台 Key，新增 `provider.byok.rejected` 错误码。新增 ADR-027 记录这几条
设计决策。

**执行**：Terminal Worker，独立任务。

**我复核的结果**：真机三种场景实测（无效 Key / 有效 Key / Key 被移除）
验证 Key 解析路径正确；`pytest`/`ruff`/`mypy`/`npm run build` 全过。

## 2026-08-19 · eval 强制门禁脚本

**问题**：CLAUDE.md 写着"新 Agent 必须有 eval 用例才能上线"，但这条规则
只活在文档里，没有代码守着——新增 Agent 不写 eval，CI 照样全绿。

**做了什么**：新增 `tests/unit/test_agent_eval_required.py`，从
`agents.registry` 实际加载的 Agent 枚举（不是手工维护的 id 白名单），
声明了 `output_schema` 的用 `SCHEMA_SAMPLES` 硬门槛，没声明的退回
`tests/eval/agent_evals/*.eval.yaml` 内容质量用例。加了"故意注册一个缺
eval 的假 Agent，断言门禁真的会红"的自证用例。

**执行**：Terminal Worker，独立任务，照抄 `test_pricing_no_constants.py`
的模式。

**我复核的结果**：`pytest -q`/`ruff`/`mypy` 全过；假 Agent 自证用例实测
会拦下（不是摆设）。
