# 一致性引擎（Consistency Engine）

> **这是本项目的核心技术难点，也是唯一真正的护城河。**
>
> Router / Director 的编排是产品体验加分项，可以被抄。
> 一致性做不好，产品直接不可用——用户在第 3 个镜头看到主角变脸就会关掉页面。
>
> 本文档的地位等同于 `03_AgentSystem.md`，不是扩展功能。

---

## 1. 问题定义

一部 5 分钟漫剧有约 60 个镜头。用户判断"这个产品能不能用"的标准不是
剧本写得好不好，而是：

```text
第 1 个镜头的主角  ==  第 47 个镜头的主角  吗？
```

需要同时保持四类一致性，它们是**互相独立的四个问题**，不能混为一谈：

| 类型 | 具体表现 | 崩坏后果 |
|---|---|---|
| **角色一致性** | 脸型、发型、瞳色、体型、服装、配饰 | 最致命，观众立刻出戏 |
| **风格一致性** | 画风、笔触、色调、线条粗细、渲染方式 | 像多个人拼的片子 |
| **场景一致性** | 同一地点在不同镜头的布局、光照、材质 | 空间关系错乱 |
| **时序一致性** | 视频片段内部的形变、闪烁、漂移 | 廉价感的主要来源 |

## 2. 分层解法与降级链

**不存在单一银弹。** 系统必须实现一条从低成本到高成本的降级链，
由 Director 根据角色重要性和预算自动选择档位。

```text
L0  提示词锁定（Prompt Lock）
    成本 0，效果 20%
    固定的角色描述词块 + 风格词块 + 负向词块 + 固定 seed
    仅够用于背景角色和空镜

L1  参考图条件化（Reference Conditioning）      ← MVP 主力
    成本低，效果 60–75%
    角色三视图作为参考图，走 IP-Adapter / 图生图 /
    多图参考接口（Seedream 4.0、可灵、万相均支持多参考图）

L2  角色 LoRA 训练                              ← 主角专用
    成本 ¥5–20 + 10–30 分钟 GPU，效果 85–92%
    每个主角训练一个 LoRA，项目级复用
    需要 15–30 张一致的角色图作为训练集（由 L1 产出后人工筛选）

L3  人脸修复 / 换脸后处理
    成本极低，效果补齐到 95%
    对已生成图做局部人脸对齐修复，兜底 L1/L2 的漂移

L4  人工介入
    用户在角色库里替换/重绘某一张，系统重新条件化后续镜头
```

**Director 的选择策略：**

```text
主角（出场 > 10 镜）        → L2 + L3
配角（出场 3–10 镜）        → L1 + L3
背景角色 / 群演              → L0
用户预算为经济档            → 全部降一级
用户已上传自有角色参考图    → 跳过 L1 生成，直接用用户图
```

## 3. 角色资产流水线

**关键认知：角色不是"Character Agent 顺手生成的一段描述"，
它是一条独立的、需要人工确认的资产生产线。**

```text
小说文本
   ↓
角色抽取（LLM）：姓名、年龄、外貌、性格、服装、出场频次
   ↓
角色设定卡（结构化 JSON，非自然语言）
   ↓
基准立绘生成（正面全身，中性表情，中性光照，纯色背景）
   ↓
★ 人工确认 Gate（这是最重要的一道门）
   ↓
三视图扩展（正面 / 侧面 / 背面）
   ↓
表情集（平静 / 惊讶 / 愤怒 / 悲伤 / 微笑）
   ↓
服装集（如剧情需要换装）
   ↓
[主角] LoRA 训练集筛选 → 训练 → 验证
   ↓
角色资产包冻结（character_profile 锁定，版本化）
   ↓
后续所有镜头引用该资产包
```

**为什么基准立绘的人工确认是最重要的门：**
它是唯一一个"用户花 30 秒确认，能避免后面 60 个镜头全部报废"的检查点。
在这里让用户多重抽几次是**省钱**，不是浪费钱（见 `19_UnitEconomics.md` 第 2.3 节）。

## 4. 风格锁定

风格漂移和角色漂移是**两个独立问题**，很多实现会混淆。

项目创建时确定并冻结一个 `style_profile`：

```yaml
style_profile:
  id: style.anime_suspense.v1
  base_model: <模型/检查点标识>
  style_lora: <可选，风格 LoRA>
  positive_tokens: "..."        # 固定追加到每个 prompt
  negative_tokens: "..."        # 固定负向词
  color_grading: "低饱和, 冷调, 高对比"
  line_weight: "中等"
  render_mode: "赛璐璐"
  sampler: <采样器>
  cfg: 5.5
  seed_strategy: "project_fixed_base + shot_offset"
```

约束：

- `style_profile` 一旦有镜头产出即**冻结**，修改必须创建新版本并明确告知
  用户"已生成的镜头需要重新生成"
- Prompt Agent 生成的镜头提示词**只描述内容**，风格词由系统统一注入，
  禁止 Agent 自行编写风格词——这是画风漂移的头号来源
- 换 base_model 等价于换风格，必须走版本流程

## 5. 音频优先的时间线（重要的流程修正）

> 这条修正原 `03_AgentSystem.md` 的 Agent 顺序错误。

原流程 `storyboard → image → video → audio` 会导致音画对不上：
视频片段是固定 5 秒，但一句台词可能需要 3.2 秒或 7.8 秒。
事后拉伸视频会变形，剪掉会丢内容。

**正确顺序（音频优先）：**

```text
剧本定稿
   ↓
台词/旁白拆分到镜头
   ↓
TTS 合成 → 得到每句的【真实音频时长】
   ↓
按真实时长反推每个镜头的目标时长
   ↓
镜头时长 → 决定该镜头需要几段视频、是否需要运镜补足
   ↓
关键帧生成（首帧 / 必要时尾帧）
   ↓
图生视频（按目标时长切段）
   ↓
时间线装配（视频轨 + 配音轨 + BGM 轨 + 字幕轨）
   ↓
ffmpeg 渲染
```

含义：**Audio Agent 必须在 Image / Video Agent 之前执行**，
`03_AgentSystem.md` 和 `04_SkillSpec.md` 的 agents 顺序需要相应调整。

## 6. 一致性的量化验收

QA 不能靠"感觉像"。必须有可计算的指标，否则 QA Agent 无从判断，
也无法回答"这次改动到底让一致性变好了还是变差了"。

| 指标 | 方法 | 阈值（建议初始值） |
|---|---|---|
| 角色相似度 | 人脸 embedding 余弦相似度 vs 基准立绘 | ≥ 0.75 通过，< 0.60 直接重生成 |
| 风格一致性 | CLIP image embedding 与风格锚图的距离 | 镜头间标准差 ≤ 阈值 |
| 场景一致性 | 同场景镜头的色调直方图距离 | 经验阈值 |
| 时序稳定性 | 相邻帧光流幅度突变检测 | 检出闪烁/形变 |
| 字幕对齐 | 字幕时间戳 vs 音频 VAD 边界 | 偏差 ≤ 120ms |

这些指标必须**落库**（`shot_quality_scores` 表），因为它们同时是：
- QA Agent 的自动重试依据
- `19_UnitEconomics.md` 里 `retry_factor` 的数据来源
- `22_AgentEval.md` 回归测试的评分依据

## 7. 数据模型要求

`09_Database.md` 现有的 `characters` / `character_versions` 只有版本字段，
**撑不起一致性**。必须补充：

```text
character_profiles
  id, project_id, character_id, version
  appearance_json          -- 结构化外貌，非自然语言
  base_portrait_asset_id   -- 基准立绘
  turnaround_asset_ids[]   -- 三视图
  expression_asset_ids[]   -- 表情集
  outfit_asset_ids[]       -- 服装集
  lora_artifact_id         -- 训练产出（可空）
  consistency_tier         -- L0/L1/L2/L3
  locked_at                -- 冻结时间
  embedding                -- 人脸特征向量（pgvector 的真实用途）

style_profiles
  id, project_id, version, ...（见第 4 节字段）
  locked_at

shot_conditioning
  shot_id
  character_profile_ids[]  -- 本镜头引用了哪些角色资产
  style_profile_id
  reference_asset_ids[]
  seed
  resolved_prompt          -- 最终实际下发的完整提示词（必须存，用于复现）

shot_quality_scores
  shot_id, metric, value, threshold, passed, measured_at
```

> `resolved_prompt` 必须持久化。没有它，任何"为什么这一镜崩了"
> 的问题都无法排查，也无法复现。

> 这同时确定了 `pgvector` 的用途（原 `02_Architecture.md` 列了它但没说用来做什么）：
> **存角色人脸 embedding，用于一致性检索与校验**，不是用来做 RAG。

## 8. 实施优先级

一致性引擎不要一次做完，按此顺序：

| 阶段 | 内容 | 里程碑 |
|---|---|---|
| 1 | L0 提示词锁定 + style_profile 冻结 + resolved_prompt 落库 | M1 |
| 2 | L1 参考图条件化 + 角色资产流水线 + 基准立绘确认门 | M1 |
| 3 | 角色相似度量化 + 自动重试 | M2 |
| 4 | L3 人脸修复后处理 | M2 |
| 5 | L2 角色 LoRA 训练（依赖 GPU Runtime） | M4 |

**M1 必须做到 L1**。只有 L0 的产品不值得给用户看。

## 9. 待验证的开放问题

以下问题**文档无法回答，必须靠手工做一部片来验证**（见 `16_FirstMilestone.md`）：

1. L1 参考图条件化在当前主流模型上的实际相似度能到多少？
2. 角色 LoRA 需要多少张训练图才能稳定？训练一次多久？
3. 图生视频环节角色漂移有多严重？首帧锁定能否传导到整段？
4. 换装、侧脸、远景、多人同框——哪个场景最容易崩？
5. 人脸 embedding 相似度阈值定在多少，与人的主观判断最吻合？

**在回答这 5 个问题之前，不要开始写一致性引擎的生产代码。**
