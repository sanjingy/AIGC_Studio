# 单位经济模型（Unit Economics）

> 本文档回答一个 `08_BillingCredits.md` 没有回答的问题：
> **一部片子到底要花多少钱，我们应该卖多少钱。**
>
> 价格采集日期：**2026-08-16**。所有价格都是**参数**，不是常量。
> 实现时必须落到 `pricing_rules` 表并支持热更新，禁止写进代码。

---

## 0. 为什么这份文档必须存在

原 `03_AgentSystem.md` 中 Router 输出示例写的是：

```json
"estimated_credit_range": [2000, 5000]
```

按本文档推算，标准档一部 5 分钟漫剧的**成本**约 14500 Credits，**售价**约 29000 Credits。
原估值低了 **6–15 倍**。这不是笔误，是因为从来没人算过。

一个反例证明价格不可写死：**DeepSeek 于 2026-08-17 起调价，高峰时段输出价格上涨 350%**
（V4-Flash 输出 ¥2/M → ¥9/M）。任何把单价 hardcode 的实现，会在一夜之间毛利转负。

### 1.4 语音合成（TTS）

火山引擎豆包语音：**音色年费约 ¥150/音色/年** + 字数包（10 万字起售）。

结构上是**固定成本为主、边际成本近似为零**。单片摊薄后 < ¥1。
但要注意：一部剧 5 个角色 = 5 个音色 = ¥750/年的固定支出，
如果做声音克隆（每个项目角色音色不同），成本模型会完全不同，需要单独评估。

## 2. 基准场景：一部 5 分钟悬疑漫剧

### 2.1 生产参数假设

```text
成片时长              300 s
平均镜头时长          5 s
镜头数                60
每镜头关键帧          1 张（首帧）
图片废片率            2.5   （生成 2.5 张得 1 张可用）
视频废片率            1.5   （生成 1.5 条得 1 条可用）
前置资产              3 角色 × 8 张 + 6 场景 × 3 张 = 42 张（含废片 ×2 = 84 张）
LLM 累计              输入 60 万 token / 输出 12 万 token
TTS                   约 1400 字
```

> **`废片率` 是本模型中最不确定、也最重要的参数。**
> 初始值 image=2.5 / video=1.5 是经验拍值，**必须**在 M1 上线后用 `tasks` 表
> 的真实数据每周重新拟合。这两个数字每降 0.1，标准档单片成本下降 ¥4–9。

### 2.2 三档成本测算

**经济档**（万相 Flash 视频 + 本地 ComfyUI 出图 + DeepSeek Flash 空闲）

| 项 | 计算 | 金额 |
|---|---|---|
| LLM | 0.6M×¥1.5 + 0.12M×¥4.5 | ¥1.44 |
| 图片 | 234 张，本地 GPU 电费 | ¥0.30 |
| 视频 | 60×1.5 = 90 次 × ¥0.50 | ¥45.00 |
| TTS | 1400 字 | ¥0.50 |
| 隐性 | | ¥3.00 |
| **合计** | | **≈ ¥50** |

**标准档**（Seedance pro fast + Seedream 4.0 + DeepSeek Flash 高峰）

| 项 | 计算 | 金额 |
|---|---|---|
| LLM | 0.6M×¥3 + 0.12M×¥9 | ¥2.88 |
| 图片 | (60×2.5 + 84) = 234 张 × ¥0.21 | ¥49.14 |
| 视频 | 90 次 × ¥1.03 | ¥92.70 |
| TTS | | ¥0.50 |
| 隐性 | | ¥5.00 |
| **合计** | | **≈ ¥150** |

**高质档**（可灵 v3 pro + Seedream 4.0 + DeepSeek Pro）

| 项 | 计算 | 金额 |
|---|---|---|
| LLM | 0.6M×¥9 + 0.12M×¥27 | ¥8.64 |
| 图片 | 234 张 × ¥0.21 | ¥49.14 |
| 视频 | 90 次 × ¥3.20 | ¥288.00 |
| TTS | | ¥0.50 |
| 隐性 | | ¥9.00 |
| **合计** | | **≈ ¥355** |

### 2.3 成本结构结论（本文档最重要的一页）

| 档位 | 视频占比 | 图片占比 | LLM 占比 |
|---|---|---|---|
| 经济档 | 90% | 1% | 3% |
| 标准档 | 62% | 33% | 2% |
| 高质档 | 81% | 14% | 2% |

**三条硬结论：**

1. **LLM 成本占比 2–3%，可以忽略。**
   不要为了省 token 去阉割 Router / Director 的上下文，那是捡芝麻丢西瓜。
   该用好模型的地方（分镜质量直接决定废片率）就用好模型。

2. **成本 100% 集中在"视觉产物的废片率"上。**
   所以 `17_ConsistencyEngine.md` 不是锦上添花的功能，
   它是**直接的成本中心**——一致性做好，废片率从 2.5 降到 1.5，单片省 ¥20+。

3. **分级渲染是最大的成本杠杆。**
   预览用便宜模型让用户审核，定稿才用贵模型。见下节。

## 3. 分级渲染策略（省 40–60%）

```text
Gate 5 分镜确认
   ↓
预览档渲染：万相 Flash / 低分辨率 / 无重试
   60 镜 × ¥0.50 = ¥30
   ↓
用户审核，标记哪些镜头需要重做
   ↓
定稿档渲染：仅对确认镜头，用高质模型，重试率降到 1.1
   60 镜 × 1.1 × ¥3.20 = ¥211
   ↓
合计 ¥241  vs  全程高质档 ¥288
```

对标准档效果更明显：预览 ¥30 + 定稿 60×1.1×¥1.03 = ¥68 → **合计 ¥98 vs ¥150，省 35%**。

产品含义：**"预览—确认—定稿"必须是默认流程，不是可选项。**
这条改动同时降低成本和提升用户满意度，是本次评审性价比最高的一条建议。

## 4. Credits 定价

### 4.1 汇率

```text
1 Credit = ¥0.01
100 Credits = ¥1
```

选这个比例的理由：整数运算、便于展示、促销赠送时不出现小数、
与国内用户对"点数"的直觉一致。**汇率一旦公布不可更改**，
调价通过调整"每个能力消耗多少 Credits"实现，不要动汇率。

### 4.2 定价与毛利

| 档位 | 成本 | 建议售价 | Credits | 毛利率 |
|---|---|---|---|---|
| 经济档 | ¥50 | ¥98 | 9800 | 49% |
| 标准档 | ¥150 | ¥288 | 28800 | 48% |
| 高质档 | ¥355 | ¥688 | 68800 | 48% |

**毛利率目标 ≥ 45%**。这个数字不是拍的，它需要覆盖：
存储与带宽、内容审核、退款与重跑、客服、支付通道费（~1%）、以及上游随时涨价的缓冲。

**对比人工外包**：一部 5 分钟漫剧外包制作报价通常在 ¥2000–5000。
按 ¥288 定价有明确价格优势，前提是**成片可用率**足够高——
这再次指向一致性引擎。

### 4.3 充值档位

| 档位 | 售价 | 到账 Credits | 赠送 |
|---|---|---|---|
| 体验包 | ¥50 | 5,000 | 0% |
| 标准包 | ¥298 | 32,000 | +7% |
| 专业包 | ¥998 | 115,000 | +15% |

赠送额度在 `credit_transactions` 中必须与充值本金**分账记录**
（`ADMIN_GRANT` vs `TOPUP`），因为退款只退本金部分。

## 5. 免费额度设计

**反面做法：免费送一部完整片。**
成本 ¥150/人，按 5% 付费转化率 → CAC = ¥3000。必死。

**建议做法：免费到"看得见价值"，付费在"产生视觉成本"之前。**

```text
免费：注册 → 上传小说 → 故事结构 → 角色设定 → 分镜脚本
      成本 ≈ ¥3（纯 LLM）

免费：1 个镜头的试片（预览档）
      成本 ≈ ¥2

合计新用户获取成本 ≈ ¥5
按 5% 转化率 → CAC ≈ ¥100，首单毛利 ¥138 即可回本
```

这条同时是**产品设计约束**：分镜脚本必须做得足够好看、足够有信息量，
它是免费到付费的转化点。

## 6. 估价公式（供 Router Agent 使用）

```python
estimated_cost = (
      shots * frames_per_shot * image_price * image_retry_factor
    + shots * video_price_per_unit * video_retry_factor
    + prep_asset_count * image_price * image_retry_factor
    + llm_tokens_in  * llm_price_in
    + llm_tokens_out * llm_price_out
    + tts_chars * tts_price
) * (1 + overhead_rate)          # overhead_rate ≈ 0.03
```

实现要求：

- 所有 `*_price` 从 `model_pricing` 表读取，不查询不计算
- 所有 `*_retry_factor` 从 `pricing_rules` 表读取，由定时任务按真实数据回填
- Router 输出**区间**而非点值：`[estimate × 0.8, estimate × 1.4]`
- 预扣（reserve）按**区间上限**扣，结算时退差额（`RELEASE`）

## 7. 成本熔断（必须实现，不是可选）

| 熔断项 | 默认值 | 触发行为 |
|---|---|---|
| `project_budget_cap` | 报价 × 1.3 | 暂停项目，要求用户确认追加 |
| `task_cost_cap` | ¥20 / 单任务 | 拒绝执行并告警（防参数写错烧钱） |
| `user_daily_cap` | ¥500 / 天 | 拒绝新任务 |
| `platform_hourly_cap` | 按规模设定 | 全局降级到经济档 |
| `cost_variance_alert` | 实际/预估 > 1.5 | 告警 + 记录，用于回填 retry_factor |

> `task_cost_cap` 这一条来自真实事故经验：一个把"生成 5 秒"写成"生成 5 分钟"
> 的参数错误，配合自动重试，可以在半小时内烧掉四位数。

## 8. 盈亏平衡

```text
标准档单片毛利      ¥138
固定成本（2 人 + 服务器）  ≈ ¥65,000 / 月

盈亏平衡点 = 65000 / 138 ≈ 471 部 / 月 ≈ 每天 16 部
```

**这是整个项目最应该贴在墙上的数字。**
所有功能优先级都应该用"它能不能帮我们更快到每天 16 部"来排序。
按这个标准衡量，AutoDL GPU 租赁（`07_AutoDL.md`）对该指标的贡献接近于零。

## 9. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 上游涨价（如 DeepSeek 2026-08-17 涨 350%） | 毛利直接转负 | `pricing_rules` 热更新 + 成本告警 + 多 Provider failover |
| 汇率波动（Seedream 等按美元计价） | 5–10% 成本波动 | 定价预留缓冲，按月复核 |
| 废片率高于假设 | 单片成本翻倍 | 熔断 + 分级渲染 + 一致性引擎 |
| 用户无限重试 | 单项目亏损 | `project_budget_cap` |
| 免费额度被刷 | 获客成本失控 | 实名 + 设备指纹 + 免费额度不含视频生成 |
