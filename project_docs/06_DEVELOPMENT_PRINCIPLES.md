# 统一开发原则

> 2026-10-08，经负责人要求统一。本文是产品定位、工作台方向、模块复用和验收原则的统一入口；历史记忆与旧计划冲突时，以本次明确决定为准。架构契约以最新有效 ADR 为准，被后续 ADR 替代的条款不再生效。

## 1. 产品与优先级

面向普通外部创作者的托管 SaaS。输入小说原文或创意，经过剧本、角色、场景、分镜，最终下载逐镜带配音的 MP4。专业工作台形态服务创作，不以内部运维人员的理解能力作为默认前提。

优先完成这条创作链路。视频、配音和 MP4 属于目标，尚未交付的能力不得宣传为可用。范围边界沿用当前有效 ADR，不因一次界面改造扩大产品范围。

## 2. 模块开发先查 GitHub，优先套用成熟代码

每次新开发或实质重做一个模块，在选型和编码前必须先搜索 GitHub 的同类功能模块。候选仓库必须在调研时至少有 **1,000 stars**；可用 GitHub 搜索条件 `stars:>=1000`。该规则同时适用于前端和后端，不仅限于供应商适配。

找到功能匹配、许可证允许使用且能接入当前架构的候选，就优先套用其现成代码，采用依赖接入或移植所需模块的方式，完成必要适配；不默认从头自研，也不为了复用整套替换现有系统。

实施前在对应模块文档或任务书记录：搜索词和日期、仓库链接、当时星数、许可证、拟复用的目录/模块、来源版本或 commit、接口与依赖适配方式。移植代码保留版权与许可证说明，交付时注明来源。

星数是候选门槛，不代替功能匹配、维护情况与许可证核对。没有符合条件的可用模块时，记录搜索结果及不适用原因，由 Lead 决定补充调研或自研；不得跳过搜索，也不得把低于 1,000 stars 的仓库算作满足本规则的候选。一般适配决定不额外请求负责人确认，产品方向和架构变更沿用既有流程。

## 3. 工作台与视觉

以 Reelbench 参考工作台为当前方向：紧凑项目顶栏、模块导航、对象目录、编辑与预览主区。对象定位、动作范围、内容编辑和生成结果必须清楚；导航位置与生产状态分别表达。

采用暖黑底与克制金色强调，使用 `globals.css` 的 `.theme-reelflow` 语义 token。旧 teal、霓虹青、Studio Ledger 蓝灰以及胶片齿孔不再是工作台设计要求。保留 AIGC Studio 品牌和现有权限、计费、审核契约。参考截图只作为视觉依据，不把宣传图上的操作当作已验证能力。

图片和文本是主体，减少无内容卡片、大标题和重复信息。系统字体、正文 14–16px、表格最小 13px；支持窄屏、键盘焦点和无 body 横向滚动。每个页面明确当前对象、可做动作、动作后果和下一步，技术信息只在帮助用户判断时呈现。

## 4. 真实能力与生成控制

仅使用已实现、部分实现、预留、仅设计、未实现五种状态。占位、类型声明、Mock 跑通均不能冒充真实功能交付。

测试环境可用 Mock；非测试环境缺模型配置必须返回可修正的错误。生成失败不静默换连接或平台 Key。四道内容确认门、画风锁定、成品提示词与产物溯源遵从 ADR-036～039。修改上游内容后识别旧词和旧图过期，不悄悄重新付费生成。

## 5. 工程实施

先记录 GitHub 复用选型，再明确模块需求、数据模型、接口和验收条件，然后实施。跨模块架构改变先更新 ADR。保留任务状态唯一来源、多租户隔离、计费账本幂等与一致性约束；第三方模块通过现有契约接入。

Lead 负责方向、范围和最终验收，Worker 按任务范围实施。同一文件和契约避免并行修改。视觉任务沿用 GPT 先出完整页面代码、Claude 再整理工程实现的历史分工；新规则要求先完成复用搜索，两阶段不得绕开。

## 6. 验收与交付

工程检查是地板；产品验收同时检查容易理解、操作连贯和结果满意。

- 用 1440×900、1280×800、390×844 检查布局、长文本、加载、空状态、错误和键盘操作。
- 从首次进入开始走创建、编辑、确认、生成、恢复与刷新；用户应能辨认当前对象和下一步，批量动作明确范围及费用影响，未保存内容有保护。
- 用真实 API 验证持久化、刷新、上传与任务状态。Mock 结果明确标为 Mock，不能替代真实后端闭环。
- 涉及生成质量时用真实作品样本核对原文忠实度、角色/场景/画风一致性及提示词对应关系，记录样本、实际模型、结果与未通过项；未做真实生成不得宣称质量已通过。
- 工程通过、产品交互通过、真实生成质量通过和部署生效分别记录。交付核对服务实际读取的构建目录、版本与新路由，并打开网页查看效果。

不为验证擅自增加付费调用；已授权范围内继续执行。提交、发布等沿用既有授权约定。

## 7. 文档与历史

`project_docs/` 是唯一知识入口。规则与目标以负责人最新明确决定、本文和最新有效 ADR 为准；实现事实以代码、迁移及对应验证证据为准。代码已存在不等于产品已验收，历史测试通过不等于当前部署已生效。

旧阶段记录保留时间与出处，不能覆盖后续决定。总状态首页汇总最新快照；模块文档和阶段计划保留具体证据；设计系统集中维护视觉细节，其他文档引用它，不各自定义调色板。
