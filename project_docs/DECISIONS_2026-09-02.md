## 1. 产品终点（Q3、Q4、Q19）

- **用户**：外部创作者，通过我们托管的 SaaS 使用，多租户按 `org_id` 隔离。不是自托管，不是 ComfyUI 面板。
- **输入**：小说原文，或一句话/一段创意（可附参考内容）。
- **终点（M2）**：项目内每个镜头都能产出一条**带配音的 MP4** 并下载；支持批量下载全部镜头。
- **明确不做（M2 内）**：整集时间线合成、字幕、BGM、转场、剪映草稿导出、支付、团队成员、运营后台、合规审核、自建 GPU/ComfyUI。
- 用户拿到逐镜 MP4 后，自己决定在平台上拼接（后续版本）还是去剪映。

## 3. 生产流程（Q8、Q14、Q15）

复刻 ReelBench 登录后可见的"从提示词到视频"流程（记录见 `_research/reelbench_ux_review.md` §2），在其基础上按我们的后端权威改造。

### 3.1 目标流程

```
入口：小说原文 / 创意（一句话 + 可选参考）
  → 路线判断（Router）
  → 情节目录 + 分集大纲
  → 剧本（集 → 场 → 节拍 → 台词）            【门：确认剧本】
  → 角色档案 → 场景档案（串行；各自出基准图，可 AI 生成 / 从资产库选 / 本地上传）
  → 分镜（集 → 镜；每镜：时长、景别、运镜、台词、出场人物、场景、画面提示词）
                                              【门：确认分镜】
  → 每镜首帧图（多候选 + 一个当前版）
  → 每镜配音（台词 TTS，得到真实时长；镜时长以音频为准回写）
  → 每镜视频：镜按视频模型的单段上限切成 N 段，每段一次图生视频（多候选 + 当前版）
  → 每镜 MP4：段视频拼接 + 配音混音（ffmpeg，无字幕无 BGM）
  → 下载
```

### 3.2 从 ReelBench 取什么、不取什么

| 项 | 取舍 | 理由 |
|---|---|---|
| 创意项目入口（一句话/一张图起步） | **取** | 只是把 `plot_index` 的输入从"小说"放宽 |
| 分集大纲 | **取** | 剧本按集导航的前提 |
| 改编取舍 / 爽点表 | 不取（P2） | 叙事质量工具，不挡出片 |
| 角色/美术/剧本并行迭代 | **不取** | 串行过门是我们比它可靠的地方 |
| 层级：集 → 镜 → 段 | **取，但语义不同**：我们的"段"是**镜内的视频生成单元**，不是 ReelBench 的"一组镜头" | 见 3.3 |
| 每镜/每段视频带版本、生成服务、比例、分辨率 | **取** | 见 §5 候选版本 |
| 上游变更传播 | **取最小版**：只标记"过期"，由用户决定"重出"或"保留当前版"，不自动传播 | 自动传播的影响集计算是 P1 |
| 图片编辑（图生图 + 多参考图） | 不取（M2 后） | Provider 抽象无 `init_image`，会同时动 Gateway、计费、BYOK |
| 字段双击可改 + 变更历史 + 批次撤销 | **取**，后端已由 ADR-029 落地，前端待接 | — |

### 3.3 镜与段：视频最小单元（Q15）

- 视频**按镜生成**。镜的时长由该镜台词的 TTS 真实时长推导（音频优先），并受最小/最大时长约束。
- 每个视频模型有**单段最大时长**（万相约 5 s，Seedance 15 s 以上）。镜时长超过上限时，镜切成 N 段，每段一次图生视频调用，段拼成镜。
- **视频模型（至少是它的单段上限）是分镜阶段的输入**：分镜阶段就要确定每镜时长和段数分配，不能出图之后再算。
- 段与段之间的首帧如何衔接（用上一段末帧 / 同一首帧 / 首尾帧模式）是**待定设计**：由媒体模块文档提方案，Lead 定。
- 第一条打通用现有 DashScope 万相；Seedance 的 Key 由负责人后续提供用于测试。

### 3.4 领域模型（Q8 ③）

- **不实体化**。角色/场景/分镜正文继续存 `projects.current_state_json`，字段级修改走 ADR-029 的 JSON Patch 写路径。实体化（ReelBench 式每个角色一行）放 M2 之后。

## 4. 供应商与模型选择（Q10、Q16）— 推翻 ADR-024 的"档位"设想

- **用户直接选模型**，不是"经济/标准/高质"档位。ADR-024 里"暴露给用户的应是档位而非模型 ID"这一段被**推翻**，写 ADR-031 标注 supersedes。ADR-024 的两条硬约束（换模型必重算 Credits 预估；部分 role 禁用推理模型）**继续有效**。
- 能力维度：文本、图像、视频、TTS（图像编辑后续）。
- **供应商来源**：固定目录（DeepSeek、DashScope 万相/CosyVoice、后续可灵/即梦/Seedance/FishAudio/MiniMax），每家由代码内 adapter 声明能力和模型列表。**文本能力额外允许一个 OpenAI 兼容自定义端点**。视频和 TTS 不允许自定义端点（请求形状差异太大，做了就是假入口）。
- **三层默认**：组织全局默认（按能力）→ 项目覆盖（`projects.model_preference`，已有）→ **生成前临时选择**（只对本次生效，不回写默认）。
- 生成前选择必须是**界面上的模型选择按钮**，不是让用户发消息。
- Key：默认走平台 Key 扣 Credits；用户自带 Key 按 ADR-025 打折。两条并存。

## 5. 候选版本（Q17）

- 每镜的图和视频都是**多候选 + 恰好一个当前版**。每次生成新增一个候选，切换当前版不删旧候选。
- 下游（配音、视频、MP4 合成）只引用当前版，并**记录消费时用的是哪一版**，用于 §3.2 的"过期"标记。
- `GET /projects/{id}/images` 那套"取第一条就是当前版"的约定作废，改为显式 `is_current`。
- S14 的"钉基准图不删旧资产"是这条规则的雏形，顺着扩。

### 11.1 生产链路（W1）

| # | 问题 | 裁决 | 理由 |

### 12.1 合规：服务器在香港要不要备案（Lead 建议，负责人采纳）

- **ICP 备案**：只针对中国大陆境内的服务器和域名解析。服务器在香港、域名不在大陆解析，**不需要 ICP 备案**。
- **算法备案 / AIGC 标识**：《生成式人工智能服务管理暂行办法》和《深度合成管理规定》按"向境内公众提供服务"划范围，不按服务器位置。香港服务器面向大陆用户，法规上仍在范围内，执法上是灰区，最直接的风险是域名被封而不是罚款。
- **建议的顺序**：
  1. **AIGC 标识现在就做**（成本几行代码）：每镜 MP4 合成时加可见水印槽位（§11.2 裁决 12 已预留）和元数据标识；图片下载加元数据。这条不做，出事时没有任何辩护空间。
  2. **算法备案在开放注册前评估**，首批内部拉来的用户不触发；到时候找一次律师咨询，不由工程决定。
  3. **实名认证不做**，直到备案要求它。
- 这是工程侧的合规判断，不是法律意见；正式上线前需要一次法律咨询。

### 12.2 RPO / RTO（Lead 建议，负责人采纳）

- **RPO 24 小时，RTO 4 小时**。落地：PostgreSQL 每日全量备份 + 对象存储开版本控制；恢复演练在开放注册前做一次。
- 理由：首批用户的产出是可以重新生成的（花 Credits 的部分会退回），24 小时的数据丢失不致命；4 小时是一个人手动恢复一套 Compose 的合理上限。
