# 交付顺序与本地 CLI 试点（2026-09-07）

> 两件事写在一份里：**（一）** 桌面那份 `AIGC_Studio_上下文提炼.md` 第七节
> 的待办，排成一个有依赖关系的交付顺序；**（二）** 本轮实现的本地 CLI 文本
> 运行时试点，它落在这个顺序的哪个位置、为什么不该插队。
>
> **这份是排序与交接，不是新决策。** 与 ADR-034 ~ 037 冲突时以 ADR 为准；
> 与仓库其他文档冲突时以 `project_docs/` 为准。
> 试点本身的契约与限制在 [15_LOCAL_RUNTIME.md](../modules/15_LOCAL_RUNTIME.md)。

---

## 1. 排序用的三条判据

桌面那份提炼的第七节把待办列成了「正在做 / 排在后面 1~6 / 要花钱的两项」。
那是一份清单，不是顺序——里面至少有三处依赖关系没写出来。排序按这三条：

1. **会让用户看到错东西的，排在会让用户少看到东西的前面。** 前者是错误，
   后者只是缺口。`stage-map.ts` 的类型缺口（后端返回新阶段值时整条阶段条
   渲染成错的）属于前者，「每镜模型选择按钮」属于后者。
2. **今天就在漏钱的，比今天还没开始花钱的急。** `topup` 收口
   （FR-BIL-006，任何登录用户都能给自己加一百万 Credits）是唯一一条
   **已经上线且已经在漏**的。
3. **能把"要花钱验证"往后推的，先做。** M2 的 Mock 层就是这种：补齐它
   之后，拿到 seedance Key 那天改的是配置不是代码。

## 2. 交付顺序

### 第 0 波 · 正在做，不动它

**WN：四道门接前端。** 含 `stage-map.ts` 的类型缺口与场景新形状适配
（不改会渲染出 `[object Object]`）。判据 1 的典型：后端的四道门
（ADR-037）已经落地，前端还照两道门的形状渲染，用户看到的阶段条是错的。

> ADR-037 的门③要求**一次确认两样、但作用域不同**：锚点只覆盖"出卡"的场景
> （≥3 镜号 / ≥2 人同框 / 有位移），**光照覆盖全部场景**（含走内联描述的）。
> 界面上必须分开呈现——这是 2026-09-07 补充里唯一的内容，容易在实现时被
> 合并成一个列表。

### 第 1 波 · 已经在漏的洞（判据 2）

**`topup` 收口（FR-BIL-006）。** 任务书 `orca/tasks/WG.md` 已写好没派。
这是清单里唯一一条"已上线且已在漏"的，它不该排在任何一条产品能力后面。

### 第 2 波 · 让用户改了有反应（判据 1）

**景别 / 角度 / 运镜进提示词（FR-CONS-012，P0）。** 这三列今天**从未影响过
任何一张图**。字段级编辑已经上线，用户改完景别重出图会发现毫无变化——
这不是缺口，是界面在撒谎。

> 注意它与 ADR-036 的先后：ADR-036 把最终提示词的合成交给 Agent，
> `compose.py` 变成素材准备器与校验器。**先做 FR-CONS-012 会做两遍**
> （一遍拼进 `compose.py`，ADR-036 落地时再搬进 Agent 提示词）。
> 所以这一波实际的顺序是 **ADR-036 落地 → FR-CONS-012 跟着落**，
> 两件事合成一波做，不要拆开排。

**ADR-036 落地**的三条硬约束，实现时一条都不能松：

- 风格词**由系统给定值，Agent 原样照抄**，不得改写、精简、翻译或替换。
- 风格词分**三套**（人物版 / 场景版 / 视频版），**不得混用**。
  场景版要的是"空场景"——给场景参考图带人物质感词**会让模型往空场景里画人**，
  而那张图是同一场景后续所有镜头的空间基准。
- `strip_style_words` 语义反转：从"剥掉"改成"校验有没有被原样保留"，
  没保留判输出不合格走既有重试路径，**不静默放行**。

### 第 3 波 · 项目大厅的假状态

**项目大厅卡片读的是两个从不变化的列**，一个已经跑到 `done` 的项目仍然
显示「草稿 / 等待路线判断」。同样属于判据 1，但影响面比第 2 波小
（看错状态 vs. 改了没反应），所以排在后面。

### 第 4 波 · M2 的硬前置

1. **ffmpeg 进后端镜像。** 镜像里现在没有，而 ADR-034 第 6 条要求
   **生成完用 ffprobe 复核实际时长**——上游说给 8 秒和文件里真有 8 秒是
   两件事，后者才决定配音会不会被截断。没有 ffmpeg 这条防线就写不了。
2. **M2 骨架：视频 / TTS 的 Mock Provider + 合成。** 判据 3。

写 M2 骨架时要一次性把 ADR-034 的形状定死，别留"以后再改"：

- `VideoModelSpec.max_segment_ms` **作废**，改 `supported_durations:
  tuple[int, ...]`（非空）。解析不到就抛异常，**禁止任何隐性兜底**——
  不许写 `or [4, 6, 8]`，不许把不在集合里的值静默映射到邻近档位。
  这两种写法正是同行那次真实事故的根因。
- 补 `duration_resolution_constraints` 与 `reference_image_durations`
  （档位会被分辨率、带不带参考图二次收窄）。
- 取档语义是**容量**：取 ≥ 基准时长的最小合法档位，成片不裁剪；
  超过最大档位**阻断并要求用户拆镜**，不切段（ADR-034 第 4 条，N=1）。
- 换档必须**用户确认**（422 带新旧时长与新旧价格），因为换档改价，
  而 ADR-024 硬约束 1 要求换模型必须重算 Credits 预估。
- `duration_input = max(计划时长, 配音真实时长)`，**过期的配音不参与定时长**。
- **15 秒不是常量**，是"当前默认模型的档位上限今天恰好等于 15"，走配置。

同一波里顺手把 ADR-035 的形状也定了，因为候选版本会同时被视频、配音、
首帧图用到：一张 `artifact_versions`
（`resource_type, resource_key, version, asset_id, is_current, basis_digest,
task_id, created_at`）+ 部分唯一索引保证 `is_current` 恰好一条；补"弃用当前版"
动作；过期判定用 **basis digest 现算比对**，删掉"下游记录消费了哪一版"这条路。
`basis` 的边界准则一句话：**按"这一位是否改变用户拿到的成品内容"划**——
所以视觉产物的 basis **不含** model / seed / 分辨率，配音的 basis **含**
音色与语速。

### 第 5 波 · 要花钱、等负责人批

3. **本地 CLI 试点的真机端到端**（见下）。

## 3. 本地 CLI 试点排在哪

**排在第 5 波，与另外两项花钱验证并列，且优先级最低。** 理由：

- 它**不在黄金路径上**。整条"小说 → 成片"不经过它，关掉之后系统的行为与
  接入之前逐字相同。
- 它**不解决任何用户看得见的问题**。它解决的是"负责人手上有订阅、服务器上
  没有"这个成本问题，而当前的瓶颈是产品完成度不是文本成本。
- 它的**计费口径还没定**（见 15_LOCAL_RUNTIME.md §7.5）。这条路径不消耗
  上游 Key，但仍然消耗订阅额度；在"订阅额度怎么折算成 Credits"这件事定下来
  之前不该对外开放。

**为什么现在就把它实现出来**：验证它要花订阅额度，而实现它不花。
把实现做完、把安全边界钉死、把测试写全，负责人拍板那一刻就只剩"跑一次"。
反过来，先拍板再实现会让那次授权的花费卡在实现周期上。

### 3.1 这一轮实现的边界

做了：配置层（默认关、拒绝半配置、拒绝 prod）、三个端点（桥接令牌只开两条
路径）、Redis 临时邮箱（一次性完成、无重投、超时清理）、`llm.py` 的**逐请求**
路由、桌面伴随进程（stdlib、只出站、不碰登录态、不给子进程 API Key）、
两套已核实的 CLI 参数、四份桌面测试 + 四份后端测试。

**没做，且是有意的**：图片 / 视频 / 语音（绕开 Gateway 没有任何好处）、
Gemini 适配器（本机没装，写一个没法验证的等于假支持）、界面入口
（`status` 端点挂着可用，前端接入是独立的一件事）、文本任务在 `tasks` 上的
统一（既有欠账，不在本轮范围）。

### 3.2 与三条既有路径的关系

| 路径 | 谁付钱 | 本轮是否改动 |
|---|---|---|
| 平台 Key（默认） | 平台 | 否 |
| BYOK（ADR-027） | 用户的 Key | 否 |
| 项目级模型偏好（ADR-024） | 同上 | 否 |
| **本地 CLI（本轮）** | 用户桌面上的**订阅额度** | 新增，默认关 |

三条既有路径一行都没动。第四条命中时**不 failover**：退回 Gateway 是拿用户
的钱补一次他以为在用订阅的调用，退回 Mock 会把假档案写进库且不报错。

### 3.3 真机验证要跑的最小序列（等批准）

1. 服务器 `.env` 配上六个 `LOCAL_CLI_*`，只放**一个**测试项目进白名单。
2. 桌面起隧道 + `python -m apps.local_runner --doctor`，确认两个 CLI 都解析到
   原生二进制。
3. 桌面起伴随进程，服务器上 `GET /local-runtime/status` 应看到
   `runner_connected=true`。
4. 在那个测试项目上推进**一步**（建议 `plot_index`，产出最小）。
5. 看三处：`agent_runs.model_id` 是不是如实写成了 CLI 的标识、产出有没有过
   schema 校验、伴随进程日志里的用时。
6. 复核**没有**产生任何上游 API 费用。

这一步之前，任何"本地 CLI 能用"的说法都是没有证据的。

## 4. 与并发限制的关系

桌面那份提炼记了一条硬限制：**同一时刻只跑一个 Claude Worker + 负责人**，
三个 Claude 会话并行会撞账号速率限制（429）。

本地 CLI 试点会**加剧**这条限制——伴随进程跑 `claude -p` 时占的是同一个
订阅配额。所以：

- 试点选 `codex` 比选 `claude` 干扰更小（Codex 不占同一份配额）。
- 伴随进程**一次只跑一个 CLI 子进程**，这条约束在代码里，不是约定。
- 真机验证那一次，**不要**和 Claude Worker 同时跑。

服务器上只有一套容器一个库，同一时刻只能一个人跑测试——本轮的后端门禁
（`python tools/srv_check.py`）要等 WN 不在测试时由 Lead 跑。

## 5. 一句话总结

顺序是：**WN 收尾 → topup 收口 → ADR-036 + FR-CONS-012 合成一波 →
项目大厅状态 → ffmpeg + M2 骨架（一次性把 ADR-034/035 的形状定死）→
三项花钱验证**。本地 CLI 试点的代码已经就位、默认关着、关着时系统行为与
接入前逐字相同，它排在最后一波，等负责人批一次真机验证。
