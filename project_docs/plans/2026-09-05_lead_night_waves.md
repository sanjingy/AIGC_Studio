## 判断依据

产品终点（`00_CURRENT_STATUS.md`）：小说 → 5 分钟悬疑漫剧，形态是**每镜一条带配音的 MP4**。
2026-09-04 已在测试机端到端验证到"分镜首帧图"。**再往前一步就是 M2：视频 + 配音 + 合成。**

M2 一直被当成"要等负责人给视频模型的 Key"。**这个前提是错的**：
昨天的验收证明，我们的图像链路在没有 Key 时是**直接失败**而不是降级——
也就是说"没有 Key 就做不了"不是外部限制，是我们自己没建 Mock 层。
把 Mock 层补齐之后，视频、配音、合成三段可以在**不花一分钱、不等任何 Key** 的前提下全部建成，
等负责人拿到 seedance 的 Key 时只是换一个配置。

所以今晚的排序是：**先把"无 Key 也能跑通"做实，再顺着这条路把 M2 的骨架搭起来。**

## Wave 3（M2 骨架，不花钱不等 Key）

方向由同行对比的结论修正后再定稿。当前设想：

1. **视频能力的 Mock Provider**：按 ADR-032 的分段规则产出可播放的占位 MP4（用 ffmpeg 生成），
   让"镜头 → 段 → 拼接"这条链在无 Key 时可跑、可测。
2. **TTS 能力的 Mock Provider**：产出**时长真实**的静音/提示音音频。时长必须真实，
   因为 ADR 的音频优先时间线是拿配音时长反推镜头时长的——时长假了，整条时间线就是假的。
3. **合成**：ffmpeg 把"首帧图 + 视频段 + 配音"合成每镜一条 MP4。不做字幕、不做 BGM（决策记录 §1）。

这三条做完，负责人拿到 seedance 的 Key 时，改的是配置不是代码。
